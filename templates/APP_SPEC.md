# 앱 설계 명세 양식

이 양식은 AI 보완입니다. 실제 앱 정보를 채우고 모르는 값은 미확정으로 둡니다.

## 문제와 완료 조건
- 사용자와 사용 상황:
- 해결할 문제와 제외 범위:
- 입력, 형식과 크기:
- 기대 결과와 검증 가능한 완료 조건:
- 데이터 사용/공개 권한:
- 기준 시점과 최신성 요구:

## 선택한 구조
- 일반 코드/LLM 단일 호출/워크플로/단일 에이전트/다중 에이전트:
- 더 단순한 방식으로 부족한 이유:
- 근거 주제 ID와 실제 읽은 문서:
- 화면→API→하네스→도구→저장소의 요청/응답 흐름:
- 각 상태의 소유자와 사용자 격리:
- 외부 모델과 SDK 버전:
- MCP 필요 여부와 버전 카드:

## 도구와 상태
- 도구 목록과 계약 위치:
- 허용 데이터/파일/네트워크 범위:
- 상태와 허용 전이:
- 완료/거부/실패/취소/예산 소진 조건:
- 단계/토큰/금액/시간/호출 한도:
- 승인 대상, 승인 결합 값과 만료:
- 재시도 가능 오류와 횟수:
- 멱등 키의 범위와 인자 충돌 처리:
- 재시작 시 외부 부작용 대사/보상:

## 근거와 품질
- 문서 ID, 버전, 대상 키, 단위, 출처 위치를 남기는 방법:
- 누락/판독 불가/검색 없음/권한 거부 구별:
- 입력에 든 외부 지시문 처리:
- 고정 평가 사례와 임계값 근거:
- 로그 필드, 민감값 제거와 보존 기간:
- 운영 중지와 롤백 범위:

## 구현 계획과 미확정
- 가장 작은 정상 흐름:
- 우선 검증할 위험:
- 단계별 산출물과 합격 기준:
- 실제 실행 확인/오프라인 확인/설계만 작성한 범위:
- 아직 필요한 사용자 결정과 외부 의존성:
