# AGC-015 사람의 진행 기록과 기계 트레이스

## 왜 필요하고 무엇인가

진행 기록은 사람이 경로를 이해하고 기다리거나 중단할 판단을 돕는다. 트레이스는 호출과 비용을 재현하고 디버깅하는 구조화 기록이므로 서로 목적이 다르다.

## 입력에서 출력까지

실행 단계의 의도와 발견, 막힘, 부분 결과를 타임라인으로 만든다. 동시에 실행 ID, 단계 번호, 도구 인자 해시, 모델, 입력과 출력 토큰, 비용을 span으로 기록한다. 두 기록은 같은 실행 ID로 연결한다.

## 원자료의 구체적인 설명

자료의 사람용 예시는 인증 원인을 보려고 토큰 검증을 조사한다는 의도와 12개 테스트 중 3개가 만료 처리로 실패했다는 발견이다. 단순히 파일 읽는 중이라고 알리는 것보다 사람이 경로를 평가하기 쉽다.

## 적합한 조건과 피할 조건

몇 시간 걸리는 조사와 코딩에 적합하다. 사람에게 원시 토큰 수만 계속 내보내거나 자연어 보고만으로 재현 로그를 대체하는 것은 부적절하다.

## 한계와 확인할 점

자연어 이유는 검증된 사실과 추정이 섞일 수 있다. 상세 내부 추론을 저장하기보다 관찰한 근거와 선택 이유를 간결하게 남겨야 하며 비밀값과 개인정보를 로그에서 보호해야 한다.

## 설계 적용, AI 보완

현재 단계, 목적, 사용 예산, 다음 단계, 필요한 결정과 부분 결과를 이벤트 계약으로 둔다. 오류 상태와 단순 대기를 구분하고 사람 보고와 상세 로그의 접근 권한을 분리한다.

## 복습 문답, AI 작성

질문: 파일 읽는 중보다 어떤 보고가 유용한가?

답안: 어떤 문제를 확인하려고 어느 부분을 읽는지, 무엇을 발견했고 다음 행동은 무엇인지 알려야 사람이 방향을 고칠 수 있다.
