# AGC-019 에이전트 변경을 리뷰하는 기준

출처: `SRC-01`, 보관 HTML 앵커 `s-67531904`. [원자료에 기재된 사이트 원문](https://tech-learning-hub.pages.dev/courses/agentic-ai/complete-guide.html#s-67531904). 강의 개념의 재서술이며 개인 구현 성과를 뜻하지 않는다. PDF 쪽 대응과 현행 명세 검증 범위는 출처 색인에서 별도로 확인한다. 원문 링크의 현재 응답은 확인하지 못했고 본문은 보관 HTML을 기준으로 판독했다.

## 왜 필요하고 무엇인가

자동 검증을 통과시키려다 검사를 약화하거나 변경 범위를 키우는 일이 생길 수 있다. 리뷰는 결과 코드와 함께 검증 자체의 변화, 기존 구현 재사용과 예외 처리의 의미를 확인해야 한다.

## 입력에서 출력까지

변경 diff와 계획, 테스트 결과를 입력한다. 테스트 약화, 범위 초과, 유틸 중복, 예외 삼킴, 하드코딩과 의존성 변화를 자동으로 탐지하고 사람이 정당성을 판정한다. 출력은 수정 요청과 승인 근거다.

## 원자료의 구체적인 설명

자료는 assert 삭제와 skip 추가, 15파일 초과 변경, 의존성 변경, 빈 except를 검사하는 CI 예시와 커버리지 70% 예시를 든다. 작은 PR에 한 가지 행동 변경만 담는 것이 리뷰 부담을 줄이는 핵심이다.

## 적합한 조건과 피할 조건

에이전트가 만든 PR의 일관된 검토에 적합하다. assert 수나 파일 수를 품질 자체로 보거나 정규식 경고를 자동 유죄 판정으로 취급하면 안 된다.

## 한계와 확인할 점

줄 수와 커버리지 비율은 동작 검증의 충분성을 보장하지 않는다. 원자료의 shell 예시는 명령 종료 상태와 파이프 의미를 따로 검토해야 하며 그대로 완성된 CI로 간주할 수 없다.

## 설계 적용, AI 보완

필요한 경고는 AST나 테스트 정책으로 구현하고 승인된 테스트 변경 사유를 기록한다. 파일 수 상한은 분할 신호로 쓰며 보안과 요구 동작 검토를 별도로 유지한다.

## 복습 문답, AI 작성

질문: 테스트가 통과했는데 왜 테스트 diff도 봐야 하는가?

답안: 검사를 삭제하거나 skip하면 잘못된 동작도 통과할 수 있다. 구현과 함께 판정 기준이 약해지지 않았는지 확인해야 한다.
