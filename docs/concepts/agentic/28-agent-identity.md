# AGC-028 에이전트 신원과 위임 체인

출처: `SRC-01`, 보관 HTML 앵커 `s-71b5091e`. [원자료에 기재된 사이트 원문](https://tech-learning-hub.pages.dev/courses/agentic-ai/complete-guide.html#s-71b5091e). 강의 개념의 재서술이며 개인 구현 성과를 뜻하지 않는다. PDF 쪽 대응과 현행 명세 검증 범위는 출처 색인에서 별도로 확인한다. 원문 링크의 현재 응답은 확인하지 못했고 본문은 보관 HTML을 기준으로 판독했다.

## 왜 필요하고 무엇인가

사람 계정으로만 로그가 남으면 실제 행위자와 책임 주체를 구분하기 어렵다. 에이전트 신원, 대리 대상과 재위임 경로를 함께 기록해 누가 누구를 통해 행동했는지 재구성한다.

## 입력에서 출력까지

IAM에 에이전트와 소유자를 등록한다. 위임 자격증명에 주체, 행위자, 범위, 자원, 작업 ID와 만료를 연결하고 하위 위임 때 범위를 줄이고 수명을 짧게 한다. 각 단계의 행동과 회수를 기록한다.

## 원자료의 구체적인 설명

자료는 지원 에이전트가 문서 읽기 에이전트에 다시 위임하며 docs:read만 주고 부모보다 먼저 만료하는 예시를 든다. 체인 깊이 3은 교육용 상한이며 소유자 퇴사나 비활성화에 연동한 회수도 강조한다.

## 적합한 조건과 피할 조건

여러 단계의 위임과 조직 내 감사에 적합하다. 에이전트 계정을 별도 섬으로 관리하거나 사람 계정을 공유해 실제 행위자를 지우는 방식은 부적절하다.

## 한계와 확인할 점

원자료 JSON의 sub를 에이전트, act.sub를 사람으로 설명한 부분은 RFC 8693의 actor 의미와 반대다. 중첩 act도 현재 행위자와 이전 행위자의 순서를 공식 정의대로 해석해야 한다.

## 설계 적용, AI 보완

토큰 계약의 의미를 인증 서버와 합의하고 현재 actor, 대리 subject, 승인자와 소유자를 구분한다. 소유자 비활성화 시 실행 중 작업, 토큰과 예약 작업까지 중단하는 회수 절차를 시험한다.

## 복습 문답, AI 작성

질문: 하위 토큰이 부모보다 오래 살아도 되는가?

답안: 부모 위임이 끝난 뒤 하위 권한이 남으면 회수 의미가 깨진다. 범위와 수명은 하위로 갈수록 좁아지도록 강제한다.

공식 의미 보완: `act`는 현재 actor이며 중첩된 `act`는 이전 actor의 체인이다. 대리 subject와 현재 actor를 구분한다. [RFC 8693, 4.1](https://www.rfc-editor.org/rfc/rfc8693.html#section-4.1)을 대조했다.
