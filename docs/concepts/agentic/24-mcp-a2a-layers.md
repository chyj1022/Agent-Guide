## 왜 필요하고 무엇인가

MCP는 도구와 자원을 연결하는 층이고 A2A는 다른 에이전트에게 일을 위임하는 층이다. 두 연결은 대체 관계보다 한 시스템에서 함께 쓰는 관계로 이해하는 편이 적절하다.

## 입력에서 출력까지

내부 에이전트가 도구 스키마를 발견해 MCP 도구를 호출한다. 외부 업무는 상대의 능력과 입출력 계약을 보고 위임하고 작업 ID와 상태를 추적한다. 각 에이전트의 내부 도구는 상대에게 그대로 노출할 필요가 없다.

## 원자료의 구체적인 설명

자료 도식은 주문 에이전트가 배송사와 정산 에이전트에 A2A로 연결되고 각자 DB, 재고 API, 검색과 결제 서버를 쓰는 구조다. 자료는 특정 2026년 버전 변화를 설명하므로 현행 구현 계약은 별도 공식 검증 자료와 대조해야 한다.

## 적합한 조건과 피할 조건

조직 또는 구현 경계를 넘어 목표 단위 업무를 맡길 때 A2A를, 명확한 기능과 자원 접근을 연결할 때 MCP를 검토한다. 단순 함수 호출을 모두 에이전트 위임으로 포장하면 복잡도만 늘 수 있다.

## 한계와 확인할 점

MCP가 항상 짧고 동기라는 식의 설명은 전형적 예시다. 작업의 비동기 지원과 인증 방식은 실제 사용하는 명세와 구현에서 확인해야 한다.

## 설계 적용, AI 보완

연결 표에 상대 유형, 발견 방식, 입력 스키마, 인증, 시간 상한과 결과 검증을 적는다. 프로토콜 무상태성과 도메인 작업 상태를 별도로 설계한다.

## 복습 문답, AI 작성

질문: A2A를 쓰면 MCP가 필요 없어지는가?

답안: 외부 에이전트 위임과 각 에이전트의 내부 도구 사용은 다른 층이다. 둘을 함께 사용하거나 단순한 경우 필요한 층만 선택할 수 있다.
