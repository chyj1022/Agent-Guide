# AGC-005 되돌림과 피해로 위임 범위 정하기

출처: `SRC-01`, 보관 HTML 앵커 `s-e32476f0`. [원자료에 기재된 사이트 원문](https://tech-learning-hub.pages.dev/courses/agentic-ai/complete-guide.html#s-e32476f0). 강의 개념의 재서술이며 개인 구현 성과를 뜻하지 않는다. PDF 쪽 대응과 현행 명세 검증 범위는 출처 색인에서 별도로 확인한다. 원문 링크의 현재 응답은 확인하지 못했고 본문은 보관 HTML을 기준으로 판독했다.

## 왜 필요하고 무엇인가

위임 수준은 기술 난도보다 되돌릴 수 있는 정도와 오류의 피해로 정한다. 원복 명령이 있다는 사실보다 후속 시스템까지 이전 상태로 돌아가는지 확인하는 것이 중요하다.

## 입력에서 출력까지

행동별 자동 원복, 수동 복구 비용, 외부 발송, 금전 이동, 빈도와 기록 여부를 입력한다. 두 축에 배치한 뒤 승인자, 만료, 한도와 검토 방식을 정책으로 출력한다.

## 원자료의 구체적인 설명

환불 예시는 주문 ID, 금액, 이유, 90일 환불 횟수를 승인에 표시하고 10만원과 하루 20건을 예시 한도로 둔다. 메모 수정은 이력과 쓰기 승인, 티켓 생성은 사후 검토, 검색은 예외 보고로 나눈다.

## 적합한 조건과 피할 조건

위험을 도구 정책으로 바꿀 때 유용하다. 검색이라는 이유로 민감정보 반출을 저위험으로 두거나 DB 원복을 전체 업무 원복으로 간주하면 안 된다.

## 한계와 확인할 점

주문 값을 돌려도 배송 시스템이 이벤트를 받아 출고했다면 영향은 남는다. 예시 레벨과 금액은 조직에 그대로 적용할 보편 기준이 아니다.

## 설계 적용, AI 보완

자원뿐 아니라 이벤트 구독자와 외부 수신자를 영향 표에 적는다. 승인 만료 시 거부하고 정책 버전을 실제 도구 검사와 연결한다.

## 복습 문답, AI 작성

질문: DB 값을 원복하면 되돌릴 수 있는가?

답안: 후속 출고, 결제와 통보까지 확인해야 한다. 값의 원복만으로 외부 효과가 취소되지는 않는다.
