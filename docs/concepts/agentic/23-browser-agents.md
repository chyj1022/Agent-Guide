# AGC-023 브라우저 조작의 신뢰 경계

출처: `SRC-01`, 보관 HTML 앵커 `s-66a61347`. [원자료에 기재된 사이트 원문](https://tech-learning-hub.pages.dev/courses/agentic-ai/complete-guide.html#s-66a61347). 강의 개념의 재서술이며 개인 구현 성과를 뜻하지 않는다. PDF 쪽 대응과 현행 명세 검증 범위는 출처 색인에서 별도로 확인한다. 원문 링크의 현재 응답은 확인하지 못했고 본문은 보관 HTML을 기준으로 판독했다.

## 왜 필요하고 무엇인가

화면 조작은 도구 API의 좁은 권한 경계를 벗어나 로그인 세션의 넓은 행동을 사용할 수 있다. 따라서 계정, 도메인, 행동, 시간과 기록을 함께 제한해야 한다.

## 입력에서 출력까지

전용 세션과 허용 도메인, 금지 행동, 확인 대상, 최대 행동 수와 시간을 입력한다. 각 클릭과 입력 전에 페이지와 행동을 검사하고 필요한 승인을 받은 뒤 실행한다. 행동 로그와 필요한 화면 근거를 남긴다.

## 원자료의 구체적인 설명

자료는 전용 계정, 허용 목록 밖 읽기만, 자격증명 입력과 결제 등의 금지, 제출과 발송 전 확인, 최대 60행동과 15분을 예시한다. 페이지의 숨은 지시문을 데이터로 취급해야 한다는 인젝션 문제를 다룬다.

## 적합한 조건과 피할 조건

API가 없고 사람이 보던 UI를 제한적으로 조작해야 할 때 유용하다. 개인 계정 전체를 주거나 버튼 이름만 보고 위험을 판정하는 방식은 부적절하다.

## 한계와 확인할 점

읽기 전용도 개인정보 수집과 노출 위험이 있다. 단순 문자열 호스트 비교와 버튼 라벨 검사는 리다이렉트, 프레임, 모호한 UI를 충분히 다루지 못한다. 화면 기록에도 비밀이 남을 수 있다.

## 설계 적용, AI 보완

가능하면 충분한 전용 API를 먼저 사용한다. 브라우저가 필요하면 실제 목적지와 효과를 검증하고 캡처를 최소화하거나 마스킹하며 외부 지시를 실행 권한으로 승격하지 않는다.

## 복습 문답, AI 작성

질문: 페이지에 이전 지시를 무시하라고 쓰여 있으면 어떻게 다루는가?

답안: 페이지는 외부 데이터다. 상위 지시로 받아들이지 않고 허용 행동과 데이터 반출 제한을 도구 경계에서 계속 적용해야 한다.
