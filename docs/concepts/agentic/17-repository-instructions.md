## 왜 필요하고 무엇인가

저장소 규약 파일은 매번 반복 설명하던 실행 명령, 금지 사항과 완료 기준을 작업 맥락에 제공한다. 사람이 읽는 소개 문서와 달리 실행 가능한 운영 정보를 중심으로 작성한다.

## 입력에서 출력까지

프로젝트별 명령과 자주 막히는 조건을 규약으로 정리한다. 에이전트가 변경 대상에 적용되는 파일을 읽고 구현 및 검증에 사용한다. 결과는 팀이 재사용할 수 있는 작업 기준과 근거 있는 변경이다.

## 원자료의 구체적인 설명

예시는 설치, 실행, 테스트, 린트, 타입 검사를 제시하고 배포된 마이그레이션 수정, 비밀 접근, 테스트 삭제와 skip으로 통과시키기를 금지한다. 공개 API 변경 시 스키마 갱신과 UTC 저장 규칙도 포함한다.

## 적합한 조건과 피할 조건

반복 작업과 모노레포의 디렉터리별 예외에 적합하다. 기능 목록, 팀 문화, 긴 변경 이력과 비밀값을 모두 넣어 규약을 읽기 어렵게 만드는 것은 피한다.

## 한계와 확인할 점

자료는 가까운 하위 파일 우선을 설명하지만 실제 우선순위와 발견 범위는 사용하는 도구의 규칙을 확인해야 한다. 규약의 명령이 사용자 승인이나 샌드박스 제한보다 높은 권한을 주지는 않는다.

## 설계 적용, AI 보완

공통 기준은 상위 한 곳에 두고 하위에는 차이만 적는다. 실제 실행 가능한 명령인지 검증하며 반복 리뷰 지적은 가능한 경우 린트나 테스트로 옮긴다.

## 복습 문답, AI 작성

질문: 하위 파일에 상위 규약을 전부 복사하면 어떤 문제가 생기는가?

답안: 한쪽만 갱신되어 기준이 어긋나고 어떤 규칙이 유효한지 판단하기 어려워진다. 차이만 관리하는 편이 유지하기 쉽다.
