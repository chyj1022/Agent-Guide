# AGC-026 다른 조직의 에이전트 응답 검증

출처: `SRC-01`, 보관 HTML 앵커 `s-e6427894`. [원자료에 기재된 사이트 원문](https://tech-learning-hub.pages.dev/courses/agentic-ai/complete-guide.html#s-e6427894). 강의 개념의 재서술이며 개인 구현 성과를 뜻하지 않는다. PDF 쪽 대응과 현행 명세 검증 범위는 출처 색인에서 별도로 확인한다. 원문 링크의 현재 응답은 확인하지 못했고 본문은 보관 HTML을 기준으로 판독했다.

## 왜 필요하고 무엇인가

프로토콜은 상대가 정직한지, 데이터를 어떻게 쓰는지와 책임을 보장하지 않는다. 외부 에이전트의 결과는 외부 입력으로 취급해 신원과 내용, 비용과 책임을 따로 검토한다.

## 입력에서 출력까지

상대 인증과 카드 출처를 확인하고 최소 데이터만 보낸다. 타임아웃과 대기 상한으로 상태를 추적한다. 응답의 스키마, 값 범위와 자유 텍스트를 검증한 뒤 필요한 결과만 내부 판단에 전달한다.

## 원자료의 구체적인 설명

자료는 견적 -5,000원이 프로토콜을 통과해도 업무상 거부돼야 하는 사례를 든다. 식별자만 보내기, 상호 TLS, 서명 카드, 호출 한도와 서킷 브레이커를 제시하고 책임은 계약 문제라고 구분한다.

## 적합한 조건과 피할 조건

타 부서나 외부 회사에 위임하는 업무에 적합하다. 상대 자연어의 관리자 권한 실행 요청을 다음 지시로 받아들이거나 인증 성공만으로 결과를 신뢰하면 안 된다.

## 한계와 확인할 점

텍스트를 인용 블록에 넣거나 sanitize 함수로 처리하는 것만으로 인젝션이 완전히 해결되지는 않는다. 정상 완료 외에 추가 입력, 인증, 취소와 거절 상태도 빠짐없이 처리해야 한다.

## 설계 적용, AI 보완

자유 텍스트를 실행 가능한 명령과 분리하고 허용한 필드만 전달한다. 계약에는 보관, 재위임, 삭제, 사고 통지와 책임을 담고 외부 결과가 실제 실행으로 이어질 때 내부 정책을 다시 검사한다.

## 복습 문답, AI 작성

질문: 형식이 맞는 음수 견적은 왜 거부하는가?

답안: 스키마 적합성과 업무 의미의 타당성은 다르다. 가격의 유효 범위와 정책 조건을 추가로 검사해야 한다.
