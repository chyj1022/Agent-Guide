# AGT-033 에이전트 특유의 위험, 프롬프트 인젝션

출처: **SRC-02**, 보조 HTML 구간 [#s-9a1a9ab6](https://tech-learning-hub.pages.dev/courses/ai-agent/complete-guide.html#s-9a1a9ab6). 사용자 제공 PDF와의 쪽별 대응 및 판독 상태는 [출처 대응표](../../../sources/SRC-02.md)에서 구분한다. 온라인 주소는 보관 HTML의 사이트 원문 링크이며 현재 온라인 내용과의 일치는 확인하지 않았다. 이 문서는 강의 자료를 바탕으로 AI가 재서술한 개념 설명이며 개인의 구현이나 운영 성과 기록이 아니다.

## 정의와 필요한 이유

프롬프트 인젝션은 읽은 외부 데이터가 권한 있는 지시처럼 취급되는 문제다. 도구 사용 시스템에서는 잘못된 답을 넘어 정보 유출과 상태 변경으로 이어질 수 있다.

## 입력에서 출력까지

| 단계 | 구체적 내용 |
|---|---|
| 입력 | 웹페이지나 메일에 섞인 명령형 문장 |
| 처리 | 외부 내용을 출처가 있는 데이터로 구분한다. 조사에 읽기 권한만 주고 쓰기와 외부 전송은 별도 검증 및 승인 경계를 통과시킨다. |
| 출력 | 검증된 조사 결과 또는 차단된 행동 요청 |

## 자료의 예제와 학습 포인트

자료는 외부 문서의 고객 목록 발송 지시, 허용 수신 도메인 검사, 본문 민감 패턴 검사와 읽기 및 실행 역할 분리를 보여 준다.

자료의 코드와 모델명은 당시 흐름을 이해하기 위한 예시다. 이 문서는 외부 API나 원문 코드를 실행한 결과가 아니다. 구현 전 사용 중인 SDK, 전송 방식과 패키지 버전을 현재 공식 문서와 대조한다.

## 적용할 조건과 피할 상황

검색, 이메일, 파일과 MCP 결과를 읽는 앱의 위협 모델에 적합하다. 구분자나 경고 문장만을 완전한 방어로 보면 안 된다.

## 실패 조건과 해석 경계

요약문에도 공격 지시가 남을 수 있으므로 원문을 요약하면 인젝션이 전달되지 않는다는 자료 설명은 보장으로 받아들이지 않는다. 정규식 SQL 금지 검사도 충분하지 않다.

## AI 설계 보완

아래는 원문의 수행 결과가 아닌 **AI 설계 제안과 원문 예시의 한계 분석**이다.

요약 결과 역시 비신뢰 입력으로 다룬다. 실행기는 데이터 유래 지시를 권한으로 삼지 않고 인증된 사용자 의도와 허용 동작 및 정확한 대상에 대조한다.

## AI 작성 복습 문답

**질문:** 조사와 실행을 나누면 인젝션이 완전히 제거되는가?

**설명 답안:** 피해 경로를 줄이지만 요약에도 공격이 남을 수 있어 실행 경계에서 독립 검증이 필요하다.
