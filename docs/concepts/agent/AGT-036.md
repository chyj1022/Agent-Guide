# AGT-036 배포, 서버로 감싼다

출처: **SRC-02**, 보조 HTML 구간 [#s-98d1272f](https://tech-learning-hub.pages.dev/courses/ai-agent/complete-guide.html#s-98d1272f). 사용자 제공 PDF와의 쪽별 대응 및 판독 상태는 [출처 대응표](../../../sources/SRC-02.md)에서 구분한다. 온라인 주소는 보관 HTML의 사이트 원문 링크이며 현재 온라인 내용과의 일치는 확인하지 않았다. 이 문서는 강의 자료를 바탕으로 AI가 재서술한 개념 설명이며 개인의 구현이나 운영 성과 기록이 아니다.

## 정의와 필요한 이유

긴 에이전트 실행을 서버로 감싸려면 작업 수명과 HTTP 요청 수명을 분리해야 한다. 큐, 결과 저장과 대화 동시성이 추가로 필요하다.

## 입력에서 출력까지

| 단계 | 구체적 내용 |
|---|---|
| 입력 | 인증된 사용자의 작업 요청 |
| 처리 | 작업을 등록하고 job_id를 반환한다. 워커가 실행하며 상태와 이벤트를 저장하고 클라이언트는 커서 이후 이벤트를 조회한다. |
| 출력 | queued, running, done, failed 상태와 증분 이벤트 |

## 자료의 예제와 학습 포인트

자료는 FastAPI BackgroundTasks와 프로세스 내 JOBS 사전으로 최소 형태를 보여 주며 재시작과 다중 인스턴스에서는 DB나 Redis가 필요하다고 설명한다.

자료의 코드와 모델명은 당시 흐름을 이해하기 위한 예시다. 이 문서는 외부 API나 원문 코드를 실행한 결과가 아니다. 구현 전 사용 중인 SDK, 전송 방식과 패키지 버전을 현재 공식 문서와 대조한다.

## 적용할 조건과 피할 상황

긴 조사와 복구 가능한 서비스 API에 적합하다. 프로세스 내 background task를 내구성 있는 큐와 동일시하면 안 된다.

## 실패 조건과 해석 경계

예시의 user와 job_id를 합친 잠금은 같은 대화의 서로 다른 작업을 막지 못한다. job_id 조회에도 소유권 검사가 필요하다.

## AI 설계 보완

아래는 원문의 수행 결과가 아닌 **AI 설계 제안과 원문 예시의 한계 분석**이다.

실제 thread_id로 직렬화하고 작업 생성에 멱등키를 둔다. 큐 재전달, 워커 재시작과 취소 상태를 설계하고 오류 전문 대신 요청 ID를 제공한다.

## AI 작성 복습 문답

**질문:** 클라이언트가 요청을 끊으면 작업도 자동 취소되는가?

**설명 답안:** 그렇다고 가정할 수 없다. 취소 API와 워커의 취소 확인 정책을 별도로 정의해야 한다.
