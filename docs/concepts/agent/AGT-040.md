# AGT-040 MCP 로 도구를 표준 방식으로 붙인다

출처: **SRC-02**, 보조 HTML 구간 [#s-97c5ba24](https://tech-learning-hub.pages.dev/courses/ai-agent/complete-guide.html#s-97c5ba24). 사용자 제공 PDF와의 쪽별 대응 및 판독 상태는 [출처 대응표](../../../sources/SRC-02.md)에서 구분한다. 온라인 주소는 보관 HTML의 사이트 원문 링크이며 현재 온라인 내용과의 일치는 확인하지 않았다. 이 문서는 강의 자료를 바탕으로 AI가 재서술한 개념 설명이며 개인의 구현이나 운영 성과 기록이 아니다.

## 정의와 필요한 이유

MCP는 여러 호스트가 같은 도구 서버를 공통 규약으로 연결하도록 하는 인터페이스다. 연결 재사용성과 서버 권한을 함께 검토해야 한다.

## 입력에서 출력까지

| 단계 | 구체적 내용 |
|---|---|
| 입력 | 호스트의 도구 검색 및 실행 요청 |
| 처리 | 서버가 도구 목록과 입력 스키마를 제공하고 요청을 검증해 시스템 API를 호출한다. 클라이언트가 결과를 모델 도구로 연결한다. |
| 출력 | 표준 계약을 따른 도구 결과 |

## 자료의 예제와 학습 포인트

자료는 M개 호스트와 N개 시스템을 조합별 어댑터 M*N 대신 공통 연결 M+N으로 설명한다. 위키 search_wiki와 read_wiki, STDIO와 원격 SSE/HTTP 연결 예를 보인다.

자료의 코드와 모델명은 당시 흐름을 이해하기 위한 예시다. 이 문서는 외부 API나 원문 코드를 실행한 결과가 아니다. 구현 전 사용 중인 SDK, 전송 방식과 패키지 버전을 현재 공식 문서와 대조한다.

## 적용할 조건과 피할 상황

같은 기능을 여러 호스트에서 재사용할 때 적합하다. 작은 단일 앱의 몇 함수만 필요하면 직접 호출이 더 간단할 수 있다.

## 실패 조건과 해석 경계

M+N은 개념적 비교이며 인증과 버전 및 데이터 변환 비용이 사라지는 것은 아니다. MCP 연결은 데이터와 쓰기 권한 범위를 넓힐 수 있다.

## AI 설계 보완

아래는 원문의 수행 결과가 아닌 **AI 설계 제안과 원문 예시의 한계 분석**이다.

서버별 신뢰, 전송, 인증, 도구 권한과 결과 크기를 명세한다. 자료의 SSE 예와 어댑터 API는 현재 공식 규약 및 SDK와 대조한 뒤 적용한다.

## AI 작성 복습 문답

**질문:** MCP를 쓰면 도구가 자동으로 안전해지는가?

**설명 답안:** 아니다. 서버의 권한, 인자 검증과 호스트의 실행 정책을 별도로 통제해야 한다.
