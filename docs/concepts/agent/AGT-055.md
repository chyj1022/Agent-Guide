출처: **SRC-02**, 보조 HTML 구간 [#s-897d85f7](https://tech-learning-hub.pages.dev/courses/ai-agent/complete-guide.html#s-897d85f7). 사용자 제공 PDF와의 쪽별 대응 및 판독 상태는 [출처 대응표](../../../sources/SRC-02.md)에서 구분한다. 온라인 주소는 보관 HTML의 사이트 원문 링크이며 현재 온라인 내용과의 일치는 확인하지 않았다. 이 문서는 강의 자료를 바탕으로 AI가 재서술한 개념 설명이며 개인의 구현이나 운영 성과 기록이 아니다.

## 정의와 필요한 이유

C-07은 조회는 허용하고 송금 모의 동작 앞에서는 중단해 사람 판단 뒤 재개하는 그래프 실습이다. 대기 상태와 부작용 상태가 다르다는 점을 배운다.

## 입력에서 출력까지

| 단계 | 구체적 내용 |
|---|---|
| 입력 | A-100 잔액 확인 후 A-200으로 5만원 송금 요청 |
| 처리 | get_balance를 호출하고 transfer 앞 interrupt에서 도구와 인자를 보여 준다. SQLite 체크포인트와 같은 thread_id로 결정 값을 받아 이어간다. |
| 출력 | 승인 또는 거부 관찰과 모의 이체 기록 |

## 자료의 예제와 학습 포인트

자료 BALANCE는 A-100 520,000원, A-200 12,000원인 프로세스 내 사전이고 SENT도 목록이다. 실제 금융 API가 아니며 승인, 거부와 중단 재시작이 관찰 과제다.

자료의 코드와 모델명은 당시 흐름을 이해하기 위한 예시다. 이 문서는 외부 API나 원문 코드를 실행한 결과가 아니다. 구현 전 사용 중인 SDK, 전송 방식과 패키지 버전을 현재 공식 문서와 대조한다.

## 적용할 조건과 피할 상황

중단 재개와 승인 UI 학습에 적합하다. 이 코드를 실제 송금 시스템의 안전성 근거로 사용하면 안 된다.

## 실패 조건과 해석 경계

BALANCE와 SENT는 재시작하면 초기화되므로 체크포인트만으로 업무 원장이 보존되지 않는다. 원문은 양수 금액 검증과 목적 계좌 잔액 증가 등 실제 원장 불변식을 완성하지 않는다.

## AI 설계 보완

아래는 원문의 수행 결과가 아닌 **AI 설계 제안과 원문 예시의 한계 분석**이다.

재시작 시 pending 상태를 조회해 명시적으로 resume한다. 쓰기별 노드와 멱등키, 금액 범위 및 소유권을 검증하고 승인 인자 변경을 다시 확인한다.

## AI 작성 복습 문답

**질문:** 같은 thread_id면 처음 입력을 다시 보내도 승인 지점 재개와 같은가?

**설명 답안:** 같다고 단정할 수 없다. 대기 상태를 확인하고 사용 중 API의 재개 계약에 맞춰 호출해야 한다.
