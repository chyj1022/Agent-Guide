# AGT-028 중간에 사람 승인을 넣는다

출처: **SRC-02**, 보조 HTML 구간 [#s-3803e1f6](https://tech-learning-hub.pages.dev/courses/ai-agent/complete-guide.html#s-3803e1f6). 사용자 제공 PDF와의 쪽별 대응 및 판독 상태는 [출처 대응표](../../../sources/SRC-02.md)에서 구분한다. 온라인 주소는 보관 HTML의 사이트 원문 링크이며 현재 온라인 내용과의 일치는 확인하지 않았다. 이 문서는 강의 자료를 바탕으로 AI가 재서술한 개념 설명이며 개인의 구현이나 운영 성과 기록이 아니다.

## 정의와 필요한 이유

사람 승인 노드는 실행할 동작과 인자를 보여 주고 판단을 받을 때까지 상태를 보류한다. 승인과 실제 실행을 결합해 무단 부작용을 막는다.

## 입력에서 출력까지

| 단계 | 구체적 내용 |
|---|---|
| 입력 | 메일 발송이나 티켓 생성 요청 |
| 처리 | 위험 도구 앞에서 interrupt로 preview를 저장한다. 승인이나 거부를 받아 같은 작업을 재개하고 거부는 도구 관찰로 남긴다. |
| 출력 | approval_required, 거부 또는 승인된 실행 결과 |

## 자료의 예제와 학습 포인트

자료는 Command(resume=...)와 정적 interrupt_before, 상태 수정 후 재개를 비교한다. 웹에서는 /chat과 /approve 요청을 나누는 예를 설명한다.

자료의 코드와 모델명은 당시 흐름을 이해하기 위한 예시다. 이 문서는 외부 API나 원문 코드를 실행한 결과가 아니다. 구현 전 사용 중인 SDK, 전송 방식과 패키지 버전을 현재 공식 문서와 대조한다.

## 적용할 조건과 피할 상황

되돌리기 어려운 외부 상태 변경에 적합하다. 승인 UI 없이 프롬프트 문장만 요구하는 것은 실행 통제가 아니다.

## 실패 조건과 해석 경계

중단된 노드는 재개 시 앞부분부터 다시 실행될 수 있다. 한 노드에 이전 쓰기와 여러 interrupt가 있으면 재실행 부작용을 고려해야 한다.

## AI 설계 보완

아래는 원문의 수행 결과가 아닌 **AI 설계 제안과 원문 예시의 한계 분석**이다.

승인 ID를 사용자, 도구, 정확한 인자 해시와 만료에 묶는다. 인자 변경 뒤 재검증하고 실행은 멱등키와 별도 노드로 분리한다.

## AI 작성 복습 문답

**질문:** 체크포인트만 있으면 중복 발송이 자동으로 없어지는가?

**설명 답안:** 아니다. 재개와 재시도 시 부작용 중복을 막는 별도 실행 계약이 필요하다.
