# AGT-001 LLM 호출과 에이전트의 차이

출처: **SRC-02**, 보조 HTML 구간 [#s-8bac020d](https://tech-learning-hub.pages.dev/courses/ai-agent/complete-guide.html#s-8bac020d). 사용자 제공 PDF와의 쪽별 대응 및 판독 상태는 [출처 대응표](../../../sources/SRC-02.md)에서 구분한다. 온라인 주소는 보관 HTML의 사이트 원문 링크이며 현재 온라인 내용과의 일치는 확인하지 않았다. 이 문서는 강의 자료를 바탕으로 AI가 재서술한 개념 설명이며 개인의 구현이나 운영 성과 기록이 아니다.

## 정의와 필요한 이유

단순 호출은 한 번 답을 만들고, 워크플로는 사람이 정한 순서를 따르며, 에이전트는 관찰에 따라 다음 행동을 선택한다. 자율성의 위치가 세 구조를 구분한다.

## 입력에서 출력까지

| 단계 | 구체적 내용 |
|---|---|
| 입력 | 문서 요약 요청 또는 원인이 불명확한 장애 조사 목표 |
| 처리 | 단일 변환이면 한 번 호출한다. 정해진 조회와 정리는 코드로 연결한다. 중간 결과에 따라 로그와 코드를 더 찾아야 하면 제한된 루프를 사용한다. |
| 출력 | 요약문, 고정 절차의 처리 결과 또는 근거가 붙은 조사 결과 |

## 자료의 예제와 학습 포인트

자료는 번역과 요약, 사내 문서 Q&A, 장애 분석과 버그 수정을 대비한다. 탐색 경로가 불확정이고 도구가 필요하며 시행착오를 감당할 수 있는지 확인하도록 한다.

## 적용할 조건과 피할 상황

예측하기 어려운 조사와 디버깅에 적합하다. 정해진 분류와 담당자 전달에는 고정 흐름이 대체로 충분하다.

## 실패 조건과 해석 경계

도구를 호출했다는 사실만으로 에이전트가 되지는 않는다. RAG도 고정 파이프라인이나 탐색형 도구로 만들 수 있다.

## AI 설계 보완

아래는 원문의 수행 결과가 아닌 **AI 설계 제안과 원문 예시의 한계 분석**이다.

설계서에 다음 행동 결정 주체와 최대 재탐색 횟수를 명시한다. 최종 답변 생성과 실제 목표 달성 여부는 따로 판정한다.

## AI 작성 복습 문답

**질문:** 검색을 사용하는 모든 앱이 에이전트인가?

**설명 답안:** 아니다. 검색 순서와 횟수가 코드로 고정되어 있으면 도구를 쓰는 워크플로이다.
