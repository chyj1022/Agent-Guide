# AGT-030 스트리밍과 이벤트로 그래프 안을 들여다본다

출처: **SRC-02**, 보조 HTML 구간 [#s-fb2934e0](https://tech-learning-hub.pages.dev/courses/ai-agent/complete-guide.html#s-fb2934e0). 사용자 제공 PDF와의 쪽별 대응 및 판독 상태는 [출처 대응표](../../../sources/SRC-02.md)에서 구분한다. 온라인 주소는 보관 HTML의 사이트 원문 링크이며 현재 온라인 내용과의 일치는 확인하지 않았다. 이 문서는 강의 자료를 바탕으로 AI가 재서술한 개념 설명이며 개인의 구현이나 운영 성과 기록이 아니다.

## 정의와 필요한 이유

그래프 스트림은 전체 상태, 변경분, 모델 토큰과 사용자 정의 진행을 다른 관측 목적으로 제공한다. 내부 진단과 사용자 화면에 필요한 정보가 다르다.

## 입력에서 출력까지

| 단계 | 구체적 내용 |
|---|---|
| 입력 | 실행 중 노드 갱신과 토큰 |
| 처리 | values로 전체 상태를 확인하고 updates로 노드 변경을 본다. messages는 생성 텍스트, custom은 검색 진행 같은 업무 이벤트에 사용한다. |
| 출력 | 진단 로그와 필터링된 사용자 진행 이벤트 |

## 자료의 예제와 학습 포인트

자료는 여러 stream_mode를 함께 받고 모드별 payload를 처리하는 예와 get_state 및 update_state로 계획을 수정하는 흐름을 보여 준다. 이력에서 과거 분기로 다시 실행하는 예도 있다.

자료의 코드와 모델명은 당시 흐름을 이해하기 위한 예시다. 이 문서는 외부 API나 원문 코드를 실행한 결과가 아니다. 구현 전 사용 중인 SDK, 전송 방식과 패키지 버전을 현재 공식 문서와 대조한다.

## 적용할 조건과 피할 상황

실시간 UI, 장애 분석과 대안 경로 비교에 적합하다. 전체 상태를 그대로 브라우저에 흘리는 것은 적합하지 않다.

## 실패 조건과 해석 경계

과거 상태 재실행은 외부 부작용까지 되돌리는 기능이 아니다. 토큰 메타데이터와 이벤트 형태는 버전별로 달라질 수 있다.

## AI 설계 보완

아래는 원문의 수행 결과가 아닌 **AI 설계 제안과 원문 예시의 한계 분석**이다.

공개 이벤트 스키마를 내부 상태와 분리한다. 재실행은 읽기 전용 환경이나 부작용 비활성 모드에서 비교하고 사건 ID로 중복 표시를 막는다.

## AI 작성 복습 문답

**질문:** updates와 messages는 무엇이 다른가?

**설명 답안:** updates는 노드가 바꾼 상태를, messages는 모델 생성의 메시지 조각을 관측하는 용도다.
