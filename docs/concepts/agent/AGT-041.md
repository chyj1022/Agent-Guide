출처: **SRC-02**, 보조 HTML 구간 [#s-1615479f](https://tech-learning-hub.pages.dev/courses/ai-agent/complete-guide.html#s-1615479f). 사용자 제공 PDF와의 쪽별 대응 및 판독 상태는 [출처 대응표](../../../sources/SRC-02.md)에서 구분한다. 온라인 주소는 보관 HTML의 사이트 원문 링크이며 현재 온라인 내용과의 일치는 확인하지 않았다. 이 문서는 강의 자료를 바탕으로 AI가 재서술한 개념 설명이며 개인의 구현이나 운영 성과 기록이 아니다.

## 정의와 필요한 이유

RAG를 검색 도구로 제공하면 모델이 검색 필요성과 재검색을 선택한다. 고정 검색 파이프라인보다 유연하지만 필요한 검색을 생략하는 실패가 생긴다.

## 입력에서 출력까지

| 단계 | 구체적 내용 |
|---|---|
| 입력 | 사내 규정이나 제품 고유 정보 질문 |
| 처리 | 질문에 맞는 조각을 검색하고 doc_id와 제목 및 짧은 본문을 반환한다. 답의 출처 ID를 실제 검색 이력과 대조한다. |
| 출력 | 검색 근거가 연결된 답 또는 근거 부족 응답 |

## 자료의 예제와 학습 포인트

자료는 top_k=4와 조각당 1,200자 예를 들고 문장별 [doc_id] 인용을 요구한다. 검색이 필요한데 생략하는 질문을 평가 세트에 포함하도록 한다.

자료의 코드와 모델명은 당시 흐름을 이해하기 위한 예시다. 이 문서는 외부 API나 원문 코드를 실행한 결과가 아니다. 구현 전 사용 중인 SDK, 전송 방식과 패키지 버전을 현재 공식 문서와 대조한다.

## 적용할 조건과 피할 상황

재검색 경로가 달라지는 조사에 적합하다. 검색 1회로 충분한 업무는 고정 RAG도 비교해야 한다.

## 실패 조건과 해석 경계

검색된 ID라는 사실만으로 그 조각이 주장을 뒷받침하지는 않는다. 결과 내 지시는 외부 데이터이며 시스템 정책보다 높은 권한이 없다.

## AI 설계 보완

아래는 원문의 수행 결과가 아닌 **AI 설계 제안과 원문 예시의 한계 분석**이다.

필수 검색 조건을 실행 정책으로 점검하고 주장과 근거의 대응을 별도 평가한다. ACL과 문서 버전 및 적용 일자를 검색 계약에 넣는다.

## AI 작성 복습 문답

**질문:** 인용 ID 검사로 어떤 오류를 잡을 수 있나?

**설명 답안:** 검색하지 않은 가짜 출처는 잡을 수 있지만 실제 출처의 내용 오해까지 모두 검증하지는 못한다.
