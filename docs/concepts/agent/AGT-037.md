## 정의와 필요한 이유

증상별 진단은 최종 답을 무작정 수정하기보다 선택, 인자, 실행 결과와 반복을 궤적에서 나누어 보는 방법이다.

## 입력에서 출력까지

| 단계 | 구체적 내용 |
|---|---|
| 입력 | 도구 미호출, 오선택, 반복, 지연 또는 비용 증가 신고 |
| 처리 | 같은 입력과 설정을 고정하고 도구명, 인자와 결과를 확인한다. 원인 후보 하나를 바꾼 뒤 같은 평가 세트로 다시 측정한다. |
| 출력 | 원인 가설, 수정안과 전후 성공률 |

## 자료의 예제와 학습 포인트

자료는 search_order에 A-123과 A123을 번갈아 넣는 예로 잘못된 관찰과 반복을 설명한다. 대표 20~30개 입력을 3~5회씩 실행해 성공률과 턴 및 비용을 함께 보도록 한다.

자료의 코드와 모델명은 당시 흐름을 이해하기 위한 예시다. 이 문서는 외부 API나 원문 코드를 실행한 결과가 아니다. 구현 전 사용 중인 SDK, 전송 방식과 패키지 버전을 현재 공식 문서와 대조한다.

## 적용할 조건과 피할 상황

간헐 실패와 도구 선택 회귀를 진단할 때 적합하다. 한 번 성공한 시연만으로 개선을 판정하지 않는다.

## 실패 조건과 해석 경계

확률적 실패를 정상이라고만 설명하면 실제 결함을 놓친다. 작은 표본의 성공률 차이는 우연일 수 있다.

## AI 설계 보완

아래는 원문의 수행 결과가 아닌 **AI 설계 제안과 원문 예시의 한계 분석**이다.

실패를 입력 분포별로 나누고 동일 버전과 데이터에서 비교한다. 회귀 케이스와 불확실 구간을 남겨 반복 실험의 해석 범위를 밝힌다.

## AI 작성 복습 문답
