# AGT-007 함수 호출은 실제로 어떻게 동작하나

출처: **SRC-02**, 보조 HTML 구간 [#s-8346173f](https://tech-learning-hub.pages.dev/courses/ai-agent/complete-guide.html#s-8346173f). 사용자 제공 PDF와의 쪽별 대응 및 판독 상태는 [출처 대응표](../../../sources/SRC-02.md)에서 구분한다. 온라인 주소는 보관 HTML의 사이트 원문 링크이며 현재 온라인 내용과의 일치는 확인하지 않았다. 이 문서는 강의 자료를 바탕으로 AI가 재서술한 개념 설명이며 개인의 구현이나 운영 성과 기록이 아니다.

## 정의와 필요한 이유

함수 호출은 질문에서 실행 요청을 만든 뒤 도구 결과를 다시 모델에게 전달하는 왕복 프로토콜이다. 실행과 결과의 대응 관계를 보존해야 한다.

## 입력에서 출력까지

| 단계 | 구체적 내용 |
|---|---|
| 입력 | 서울 날씨 질문과 get_weather 명세 |
| 처리 | 모델이 city 인자를 제안한다. 호스트가 검증한 뒤 함수를 부르고 결과를 tool_call_id와 연결해 돌려준다. |
| 출력 | 날씨 관찰을 사용한 자연어 응답 |

## 자료의 예제와 학습 포인트

자료의 날씨 함수는 서울, 기온 23도와 맑음이라는 예시 데이터를 반환한다. 실제 기상청 연결이 수행된 결과가 아니다. assistant 도구 호출 메시지 뒤에 각 tool 메시지를 추가하는 순서를 보여 준다.

자료의 코드와 모델명은 당시 흐름을 이해하기 위한 예시다. 이 문서는 외부 API나 원문 코드를 실행한 결과가 아니다. 구현 전 사용 중인 SDK, 전송 방식과 패키지 버전을 현재 공식 문서와 대조한다.

## 적용할 조건과 피할 상황

실제 조회, 계산 등 모델 지식 밖 기능 연결에 적합하다. 실행 확인 없이 호출 요청을 성공 결과로 보고하면 안 된다.

## 실패 조건과 해석 경계

미등록 함수명, 잘못된 JSON, 누락 인자와 잘못된 호출 ID를 처리해야 한다. 같은 턴에 여러 호출이 올 수 있다.

## AI 설계 보완

아래는 원문의 수행 결과가 아닌 **AI 설계 제안과 원문 예시의 한계 분석**이다.

실행 요청, 실행 시작, 실행 완료를 별도 이벤트로 둔다. 조회 시각과 데이터 출처를 결과 계약에 포함한다.

## AI 작성 복습 문답

**설명 답안:** 여러 요청 중 어느 호출에 대한 관찰인지 모델과 실행기가 정확히 연결하기 위해서다.
