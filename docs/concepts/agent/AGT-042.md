# AGT-042 코드 실행 도구를 안전하게 준다

출처: **SRC-02**, 보조 HTML 구간 [#s-24c1219f](https://tech-learning-hub.pages.dev/courses/ai-agent/complete-guide.html#s-24c1219f). 사용자 제공 PDF와의 쪽별 대응 및 판독 상태는 [출처 대응표](../../../sources/SRC-02.md)에서 구분한다. 온라인 주소는 보관 HTML의 사이트 원문 링크이며 현재 온라인 내용과의 일치는 확인하지 않았다. 이 문서는 강의 자료를 바탕으로 AI가 재서술한 개념 설명이며 개인의 구현이나 운영 성과 기록이 아니다.

## 정의와 필요한 이유

코드 실행 도구는 계산과 데이터 처리를 검증 가능하게 하지만 생성된 코드를 비신뢰 입력으로 격리해야 한다. 프로세스 분리만으로 파일과 네트워크를 막을 수는 없다.

## 입력에서 출력까지

| 단계 | 구체적 내용 |
|---|---|
| 입력 | 계산이나 그래프를 위한 생성 코드 |
| 처리 | 네트워크 차단, 읽기 전용 루트, 제한된 작업 공간과 비특권 사용자로 실행한다. 메모리, CPU, 프로세스 수와 동시 실행을 제한한다. |
| 출력 | 제한된 stdout 또는 정제된 실행 오류 |

## 자료의 예제와 학습 포인트

자료는 python:3.12-slim, 메모리 256m, CPU 1개, pids 64, tmpfs 64m, cap_drop과 no-new-privileges를 예로 든다. 컨테이너도 호스트 커널을 공유한다고 설명한다.

자료의 코드와 모델명은 당시 흐름을 이해하기 위한 예시다. 이 문서는 외부 API나 원문 코드를 실행한 결과가 아니다. 구현 전 사용 중인 SDK, 전송 방식과 패키지 버전을 현재 공식 문서와 대조한다.

## 적용할 조건과 피할 상황

제한된 계산 샌드박스에 적합하다. 서비스 프로세스에서 임의 exec를 실행하는 방식은 권한 격리가 없다.

## 실패 조건과 해석 경계

자료 함수의 timeout 인자는 컨테이너 run에 실제 종료 제한으로 연결되지 않는다. 출력은 실행 뒤 자르므로 무한 출력의 수집 자체를 막지 못한다.

## AI 설계 보완

아래는 원문의 수행 결과가 아닌 **AI 설계 제안과 원문 예시의 한계 분석**이다.

별도 watchdog으로 deadline 초과 컨테이너를 중단하고 스트림 수집량을 제한한다. 이미지 고정, 호스트 mount 최소화와 강한 격리를 검토한다.

## AI 작성 복습 문답

**질문:** 메모리 제한만 걸면 코드 실행의 위험이 모두 사라지는가?

**설명 답안:** 아니다. 파일, 네트워크, 권한과 시간 및 동시성, 커널 공유 위험을 함께 다뤄야 한다.
