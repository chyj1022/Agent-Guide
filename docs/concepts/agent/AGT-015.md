## 정의와 필요한 이유

종료 설계는 정상 완료, 상한 중단, 제자리걸음과 사용자 취소를 구분하는 계약이다. 멈춘 이유를 알려야 부분 결과를 완성본으로 오해하지 않는다.

## 입력에서 출력까지

| 단계 | 구체적 내용 |
|---|---|
| 입력 | 목표, 실행 이력, 예산과 취소 신호 |
| 처리 | 새 호출 전 상한을 확인하고 정규화한 도구명과 인자의 지문으로 반복을 센다. 취소나 한도면 더 실행하지 않는다. |
| 출력 | done, limit, cancelled 같은 상태와 결과 및 재개 조건 |

## 자료의 예제와 학습 포인트

자료는 기본 12단계, 120초, 60,000토큰과 세 번째 같은 호출 안내를 예로 든다. 성공 200건의 단계 p50=3, p90=6, p99=11을 보고 상한을 조정하는 예시도 있다.

자료의 코드와 모델명은 당시 흐름을 이해하기 위한 예시다. 이 문서는 외부 API나 원문 코드를 실행한 결과가 아니다. 구현 전 사용 중인 SDK, 전송 방식과 패키지 버전을 현재 공식 문서와 대조한다.

## 적용할 조건과 피할 상황

긴 조사와 사용자 취소가 가능한 앱에 필수적이다. 모든 종료를 성공 문자열 하나로 합치면 안 된다.

## 실패 조건과 해석 경계

현재 사용량이 상한 아래여도 다음 호출이 남은 예산을 넘을 수 있다. 반복 경고만 보내고 실행 루프를 무한히 계속하는 것도 방지해야 한다.
