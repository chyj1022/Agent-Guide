# AGT-010 도구가 실패할 때, 재시도, 타임아웃, 회로 차단

출처: **SRC-02**, 보조 HTML 구간 [#s-8e6a4357](https://tech-learning-hub.pages.dev/courses/ai-agent/complete-guide.html#s-8e6a4357). 사용자 제공 PDF와의 쪽별 대응 및 판독 상태는 [출처 대응표](../../../sources/SRC-02.md)에서 구분한다. 온라인 주소는 보관 HTML의 사이트 원문 링크이며 현재 온라인 내용과의 일치는 확인하지 않았다. 이 문서는 강의 자료를 바탕으로 AI가 재서술한 개념 설명이며 개인의 구현이나 운영 성과 기록이 아니다.

## 정의와 필요한 이유

도구 신뢰성은 타임아웃, 제한된 재시도, 회로 차단과 오류 계약으로 만든다. 실패를 관찰 가능한 상태로 바꾸면 대체 경로를 선택할 수 있다.

## 입력에서 출력까지

| 단계 | 구체적 내용 |
|---|---|
| 입력 | 외부 API 조회와 일시적 429 또는 5xx 응답 |
| 처리 | 호출별 제한 시간 안에 실행한다. 재시도 가능한 실패만 간격을 늘려 반복하고 연속 장애이면 호출을 잠시 차단한다. |
| 출력 | 성공 데이터 또는 재시도 가능성 및 다음 행동을 포함한 오류 |

## 자료의 예제와 학습 포인트

자료는 기본 5초와 재시도 2회, 실패 3회와 60초 차단 같은 예시를 제시한다. 권한 없음과 존재하지 않는 자원은 같은 요청을 반복하지 않도록 알린다.

자료의 코드와 모델명은 당시 흐름을 이해하기 위한 예시다. 이 문서는 외부 API나 원문 코드를 실행한 결과가 아니다. 구현 전 사용 중인 SDK, 전송 방식과 패키지 버전을 현재 공식 문서와 대조한다.

## 적용할 조건과 피할 상황

네트워크 조회처럼 일시적 실패가 있는 도구에 적합하다. 모든 예외를 무조건 재시도하는 구현에는 부적합하다.

## 실패 조건과 해석 경계

결제 같은 부작용은 타임아웃 후 성공 여부가 불명확할 수 있다. 오류를 모두 문자열로 삼키면 보안 위반과 프로그래밍 결함도 정상 관찰로 오인한다.

## AI 설계 보완

아래는 원문의 수행 결과가 아닌 **AI 설계 제안과 원문 예시의 한계 분석**이다.

오류를 transient, invalid_input, denied, internal로 나누고 재시도 예산을 전체 deadline 안에 둔다. 쓰기에는 멱등키와 상태 조회가 필요하다.

## AI 작성 복습 문답

**질문:** 타임아웃이면 바로 같은 쓰기를 재시도해도 되는가?

**설명 답안:** 이미 수행됐을 수 있으므로 결과 확인이나 멱등성 보장 없이 재시도하면 중복 실행 위험이 있다.
