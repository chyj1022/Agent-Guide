# AGT-032 반드시 넣어야 할 안전장치

출처: **SRC-02**, 보조 HTML 구간 [#s-6a780e82](https://tech-learning-hub.pages.dev/courses/ai-agent/complete-guide.html#s-6a780e82). 사용자 제공 PDF와의 쪽별 대응 및 판독 상태는 [출처 대응표](../../../sources/SRC-02.md)에서 구분한다. 온라인 주소는 보관 HTML의 사이트 원문 링크이며 현재 온라인 내용과의 일치는 확인하지 않았다. 이 문서는 강의 자료를 바탕으로 AI가 재서술한 개념 설명이며 개인의 구현이나 운영 성과 기록이 아니다.

## 정의와 필요한 이유

운영 안전장치는 반복, 자원, 권한, 승인과 정보 흐름의 서로 다른 실패를 각각 제한한다. 하나의 가드만으로 모든 폭주를 막을 수 없다.

## 입력에서 출력까지

| 단계 | 구체적 내용 |
|---|---|
| 입력 | 실행 목표와 세션 권한 및 누적 사용량 |
| 처리 | 동일 호출과 왕복 패턴, 단계, 시간 및 토큰을 검사한다. 위험 도구는 pending 상태로 저장하고 유효한 승인 뒤에만 실행한다. |
| 출력 | 정상 결과 또는 사유가 분명한 부분 결과와 보류 요청 |

## 자료의 예제와 학습 포인트

자료는 요청당 0.50달러와 일일 50달러 예산, 반복 10회, 50,000토큰과 120초 같은 예를 든다. 사용자가 읽을 수 있는 발송 및 삭제 preview를 강조한다.

자료의 코드와 모델명은 당시 흐름을 이해하기 위한 예시다. 이 문서는 외부 API나 원문 코드를 실행한 결과가 아니다. 구현 전 사용 중인 SDK, 전송 방식과 패키지 버전을 현재 공식 문서와 대조한다.

## 적용할 조건과 피할 상황

실제 데이터를 읽거나 바꾸는 모든 도구 실행 계층에 적합하다. 한도를 문서에만 쓰고 실행 코드에서 빠뜨리면 통제가 아니다.

## 실패 조건과 해석 경계

예산을 호출 뒤에만 기록하면 마지막 호출과 동시 요청이 예산을 넘을 수 있다. 승인된 요청을 여러 번 실행하지 않도록 소비 상태가 필요하다.

## AI 설계 보완

아래는 원문의 수행 결과가 아닌 **AI 설계 제안과 원문 예시의 한계 분석**이다.

예산을 원자적으로 예약하고 정산하며 승인 상태를 pending, approved, executing, completed로 관리한다. partial은 done과 구분하고 민감 로그를 최소화한다.

## AI 작성 복습 문답

**질문:** 동일 호출 제한만 있으면 무한 반복이 없어지는가?

**설명 답안:** 아니다. 서로 다른 도구를 왕복하거나 인자를 조금씩 바꾸는 반복도 있어 전체 상한이 필요하다.
