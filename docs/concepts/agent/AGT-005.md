# AGT-005 에이전트의 구성 요소

출처: **SRC-02**, 보조 HTML 구간 [#s-06dd0a84](https://tech-learning-hub.pages.dev/courses/ai-agent/complete-guide.html#s-06dd0a84). 사용자 제공 PDF와의 쪽별 대응 및 판독 상태는 [출처 대응표](../../../sources/SRC-02.md)에서 구분한다. 온라인 주소는 보관 HTML의 사이트 원문 링크이며 현재 온라인 내용과의 일치는 확인하지 않았다. 이 문서는 강의 자료를 바탕으로 AI가 재서술한 개념 설명이며 개인의 구현이나 운영 성과 기록이 아니다.

## 정의와 필요한 이유

에이전트는 모델, 도구, 기억과 계획을 실행 제어로 묶은 시스템이다. 가드레일이 함께 있어야 동작 범위를 통제할 수 있다.

## 입력에서 출력까지

| 단계 | 구체적 내용 |
|---|---|
| 입력 | 목표, 사용 가능한 도구, 현재 작업 상태 |
| 처리 | 모델이 다음 행동을 고르고 도구가 외부 상태를 조회하거나 바꾼다. 메모리는 관찰을 유지하고 계획은 진행을 추적한다. |
| 출력 | 갱신된 작업 상태와 목표 관련 결과 |

## 자료의 예제와 학습 포인트

자료는 LLM을 판단 담당, Tools를 검색과 DB 및 파일 작업 담당으로 설명한다. 기억을 단기와 장기로, 계획을 분해와 추적으로 나누고 반복 및 비용 상한과 승인을 강조한다.

## 적용할 조건과 피할 상황

여러 단계의 도구 사용을 설계할 때 적합하다. 모든 부품을 처음부터 별도 서비스로 만들 필요는 없다.

## 실패 조건과 해석 경계

계획을 적었다고 실행 성공이 보장되지 않으며 장기 기억이 없어도 에이전트는 동작한다. 부품 수보다 책임 경계가 중요하다.

## AI 설계 보완

아래는 원문의 수행 결과가 아닌 **AI 설계 제안과 원문 예시의 한계 분석**이다.

모델 어댑터, 도구 실행기, 상태 저장소, 정책 검사기를 구분하고 각 경계의 입력과 실패 상태를 정의한다.

## AI 작성 복습 문답

**질문:** 도구와 루프만 연결하면 운영 준비가 끝나는가?

**설명 답안:** 아니다. 반복과 비용 제한, 권한, 승인, 관측과 실패 처리도 필요하다.
