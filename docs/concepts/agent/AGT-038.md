# AGT-038 따라 하기 폭주하는 에이전트를 잡아 고치기

출처: **SRC-02**, 보조 HTML 구간 [#s-e26de84d](https://tech-learning-hub.pages.dev/courses/ai-agent/complete-guide.html#s-e26de84d). 사용자 제공 PDF와의 쪽별 대응 및 판독 상태는 [출처 대응표](../../../sources/SRC-02.md)에서 구분한다. 온라인 주소는 보관 HTML의 사이트 원문 링크이며 현재 온라인 내용과의 일치는 확인하지 않았다. 이 문서는 강의 자료를 바탕으로 AI가 재서술한 개념 설명이며 개인의 구현이나 운영 성과 기록이 아니다.

## 정의와 필요한 이유

폭주 수정 실습은 정보가 없는 실패 응답이 반복 탐색을 부르는 과정을 재현하고 도구 계약을 개선하는 교육 예다.

## 입력에서 출력까지

| 단계 | 구체적 내용 |
|---|---|
| 입력 | 학생 이름만 있는 조회 요청 |
| 처리 | 빈 문자열을 반환하는 도구의 로그를 본다. 학번 형식과 대안 도구를 설명하고 found, reason, hint로 상황을 구분한다. |
| 출력 | 올바른 검색 전환 또는 이유가 있는 중단 |

## 자료의 예제와 학습 포인트

자료의 김철수 조회는 이름을 student_id에 넣고 빈 결과를 반복한다. S202601 형식과 search_student 안내를 추가한 예시 궤적에서는 이름 검색 후 학번 조회로 이어진다.

자료의 코드와 모델명은 당시 흐름을 이해하기 위한 예시다. 이 문서는 외부 API나 원문 코드를 실행한 결과가 아니다. 구현 전 사용 중인 SDK, 전송 방식과 패키지 버전을 현재 공식 문서와 대조한다.

## 적용할 조건과 피할 상황

도구 반환 형식과 설명이 반복에 미치는 영향을 학습하기에 적합하다. 제시 3회차 완료는 이번 재현 결과가 아니다.

## 실패 조건과 해석 경계

빈 배열 자체가 항상 나쁜 것은 아니다. 계약에 0건 의미가 명확하면 유효하다. hint를 권한 있는 명령처럼 신뢰해서도 안 된다.

## AI 설계 보완

아래는 원문의 수행 결과가 아닌 **AI 설계 제안과 원문 예시의 한계 분석**이다.

not_found, ambiguous, invalid_input과 denied를 구분한다. 동일 호출 및 왕복 패턴과 전체 예산 제동을 유지한 상태에서 안전하게 실패를 재현한다.
