# AGT-043 파일과 브라우저 도구

출처: **SRC-02**, 보조 HTML 구간 [#s-7a45ab34](https://tech-learning-hub.pages.dev/courses/ai-agent/complete-guide.html#s-7a45ab34). 사용자 제공 PDF와의 쪽별 대응 및 판독 상태는 [출처 대응표](../../../sources/SRC-02.md)에서 구분한다. 온라인 주소는 보관 HTML의 사이트 원문 링크이며 현재 온라인 내용과의 일치는 확인하지 않았다. 이 문서는 강의 자료를 바탕으로 AI가 재서술한 개념 설명이며 개인의 구현이나 운영 성과 기록이 아니다.

## 정의와 필요한 이유

파일과 웹 도구는 필요한 구간만 읽도록 탐색과 본문 읽기를 나누는 것이 핵심이다. 경로와 URL은 모델이 제안한 외부 입력으로 검사한다.

## 입력에서 출력까지

| 단계 | 구체적 내용 |
|---|---|
| 입력 | 파일 패턴, 줄 범위 또는 URL |
| 처리 | 목록과 검색으로 후보를 좁히고 줄 번호와 이어읽기 안내를 반환한다. 웹은 주소를 검사한 뒤 본문을 추출해 크기를 제한한다. |
| 출력 | 출처와 범위가 있는 텍스트 또는 차단 및 추출 실패 |

## 자료의 예제와 학습 포인트

자료는 파일 목록 200개, 검색 결과 100줄, 본문 4,000자와 웹 6,000자 한도를 예로 든다. 메타데이터 서버와 사설망 접근인 SSRF 및 리다이렉트 우회를 설명한다.

자료의 코드와 모델명은 당시 흐름을 이해하기 위한 예시다. 이 문서는 외부 API나 원문 코드를 실행한 결과가 아니다. 구현 전 사용 중인 SDK, 전송 방식과 패키지 버전을 현재 공식 문서와 대조한다.

## 적용할 조건과 피할 상황

큰 저장소 탐색과 공개 웹 읽기에 적합하다. 모든 파일과 HTML을 통째로 컨텍스트에 넣는 방식은 비효율적이다.

## 실패 조건과 해석 경계

출력만 자르고 파일 전체를 메모리에 읽으면 입력 자원은 제한되지 않는다. host 문자열 몇 개 차단으로 IPv6와 DNS 및 리다이렉트 SSRF를 모두 막지는 못한다.

## AI 설계 보완

아래는 원문의 수행 결과가 아닌 **AI 설계 제안과 원문 예시의 한계 분석**이다.

경로 재검증과 스트리밍 파일 읽기, 최대 다운로드 크기를 둔다. URL은 연결 전 해석한 IP와 리다이렉트의 매 단계에서 검사하고 네트워크 egress를 제한한다.

## AI 작성 복습 문답

**질문:** 웹 도구가 읽기 전용이어도 위험할 수 있나?

**설명 답안:** 내부 주소에서 자격정보를 읽거나 외부 콘텐츠 지시를 전달할 수 있으므로 범위와 신뢰 검사가 필요하다.
