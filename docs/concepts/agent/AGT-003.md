# AGT-003 워크플로가 먼저다, 에이전트는 마지막 선택지

출처: **SRC-02**, 보조 HTML 구간 [#s-d6297eac](https://tech-learning-hub.pages.dev/courses/ai-agent/complete-guide.html#s-d6297eac). 사용자 제공 PDF와의 쪽별 대응 및 판독 상태는 [출처 대응표](../../../sources/SRC-02.md)에서 구분한다. 온라인 주소는 보관 HTML의 사이트 원문 링크이며 현재 온라인 내용과의 일치는 확인하지 않았다. 이 문서는 강의 자료를 바탕으로 AI가 재서술한 개념 설명이며 개인의 구현이나 운영 성과 기록이 아니다.

## 정의와 필요한 이유

한 번 호출, 체인, 라우팅, 에이전트는 제어를 모델에 맡기는 정도가 다르다. 필요한 곳에만 판단을 위임해야 운영 경계를 이해하기 쉽다.

## 입력에서 출력까지

| 단계 | 구체적 내용 |
|---|---|
| 입력 | 요약, 초안 검토, 문의 분류, 원인 탐색 요구 |
| 처리 | 단일 변환, 고정 연쇄, 유한 경로 선택, 관찰 기반 반복 중 하나로 분해한다. |
| 출력 | 단계별 실행 주체가 드러나는 구조 |

## 자료의 예제와 학습 포인트

자료는 초안 작성과 검토는 체인, 문의 분류 후 답변 틀 선택은 라우팅, 원인 불명 버그 분석은 에이전트로 비교한다. 200줄 안이면 체인이 낫다는 조언은 강의의 경험적 기준이다.

## 적용할 조건과 피할 상황

단계 수와 분기 범위가 알려진 업무는 체인이나 라우팅이 적합하다. 열린 탐색만 제한적으로 루프에 맡긴다.

## 실패 조건과 해석 경계

코드 줄 수나 갈래 20개 같은 수치를 보편적 임계값으로 적용하면 안 된다. 요구 변경과 장애 처리 복잡성도 본다.

## AI 설계 보완

아래는 원문의 수행 결과가 아닌 **AI 설계 제안과 원문 예시의 한계 분석**이다.

고정 흐름 중 탐색이 필요한 노드 하나만 에이전트로 바꾸는 혼합 구조를 설계하고 기준선 비용을 유지한다.
