## 정의와 필요한 이유

도구 단위 테스트는 모델 판단을 제거하고 함수의 정상 동작과 경계 및 실패 처리를 확인한다. 그 다음 선택 평가와 전체 실행 평가로 범위를 넓힌다.

## 입력에서 출력까지

| 단계 | 구체적 내용 |
|---|---|
| 입력 | 임시 파일, 경로 탈출, 금지 SQL과 타임아웃 모의 입력 |
| 처리 | 도구를 직접 호출해 파일 범위와 읽기 전용 규칙 및 오류 계약을 검사한다. 이후 모델이 올바른 도구를 선택하는지만 따로 본다. |
| 출력 | 원인이 좁혀진 테스트 결과 |

## 자료의 예제와 학습 포인트

자료는 ../../ 경로, 다중 문장과 SELECT INTO, 네트워크 타임아웃을 시험한다. 도구 단위, 선택, 전체 평가 순서가 비용과 원인 분리에 유리하다고 설명한다.

자료의 코드와 모델명은 당시 흐름을 이해하기 위한 예시다. 이 문서는 외부 API나 원문 코드를 실행한 결과가 아니다. 구현 전 사용 중인 SDK, 전송 방식과 패키지 버전을 현재 공식 문서와 대조한다.

## 적용할 조건과 피할 상황

안전 경계가 있는 함수와 네트워크 래퍼 검증에 적합하다. 외부 API 연결 없이도 의미 있는 검증을 수행할 수 있다.

## 실패 조건과 해석 경계

오류 문자열에 특정 한글이 있다는 검사만으로 실행이 없었다고 증명하지 못한다. 가짜 서비스에 실제 쓰기 호출이 없었는지도 관측해야 한다.

## AI 설계 보완

아래는 원문의 수행 결과가 아닌 **AI 설계 제안과 원문 예시의 한계 분석**이다.

거부 상태, 외부 호출 횟수와 파일 및 DB 변화 없음 같은 관찰 가능한 성질을 검사한다. 라이브러리 예외 타입과 SDK 형태는 버전을 고정한다.
