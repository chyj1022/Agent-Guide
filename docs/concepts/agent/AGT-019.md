출처: **SRC-02**, 보조 HTML 구간 [#s-1840fe7f](https://tech-learning-hub.pages.dev/courses/ai-agent/complete-guide.html#s-1840fe7f). 사용자 제공 PDF와의 쪽별 대응 및 판독 상태는 [출처 대응표](../../../sources/SRC-02.md)에서 구분한다. 온라인 주소는 보관 HTML의 사이트 원문 링크이며 현재 온라인 내용과의 일치는 확인하지 않았다. 이 문서는 강의 자료를 바탕으로 AI가 재서술한 개념 설명이며 개인의 구현이나 운영 성과 기록이 아니다.

## 정의와 필요한 이유

에이전트 비용은 반복마다 이전 기록을 다시 입력하는 누적 구조에서 커진다. 호출 횟수뿐 아니라 각 관찰의 길이를 줄여야 한다.

## 입력에서 출력까지

| 단계 | 구체적 내용 |
|---|---|
| 입력 | 기본 프롬프트 토큰, 단계당 추가 기록, 반복 횟수와 단가 |
| 처리 | 매 회차 기본 입력에 이전 결과를 더해 누적 입력을 합산한다. 실제 usage를 기록하고 도구 출력 길이와 반복 한도를 제어한다. |
| 출력 | 회차별 입력 및 출력 토큰과 비용 추정 |

## 자료의 예제와 학습 포인트

자료는 base=1,500, step=800이면 10회 입력이 51,000토큰이 되는 예를 든다. 가격과 출력 비용은 강의의 계산 가정이며 현재 요금표가 아니다.

자료의 코드와 모델명은 당시 흐름을 이해하기 위한 예시다. 이 문서는 외부 API나 원문 코드를 실행한 결과가 아니다. 구현 전 사용 중인 SDK, 전송 방식과 패키지 버전을 현재 공식 문서와 대조한다.

## 적용할 조건과 피할 상황

비용 예산, 결과 축약과 반복 횟수 비교에 적합하다. 모델 단가만 비교하면 전체 실행 비용을 놓친다.

## 실패 조건과 해석 경계

제곱 증가 설명은 단계당 기록이 일정하고 전체 이력을 재전송하는 가정이다. 압축과 캐시 및 공급자 상태 처리에 따라 실제 청구 구조는 달라진다.

## AI 설계 보완

아래는 원문의 수행 결과가 아닌 **AI 설계 제안과 원문 예시의 한계 분석**이다.

총입력 n*b+s*n*(n-1)/2로 가정을 적는다. 도구 자체 사용료, 캐시된 입력과 지연도 따로 측정하고 상한 전 예약 예산을 반영한다.

## AI 작성 복습 문답

**질문:** 긴 도구 결과 하나가 특히 비싼 이유는?

**설명 답안:** 그 결과가 이후 여러 회차 입력에 반복해서 포함되기 때문이다.
