## 정의와 필요한 이유

C-03은 자연어 질문을 DB 스키마에 맞는 조회 SQL로 바꾸고 실행 결과를 해석하는 실습이다. 쓰기 제한과 결과 크기 통제가 중요하다.

## 입력에서 출력까지

| 단계 | 구체적 내용 |
|---|---|
| 입력 | 도시별 매출, 월별 비교 또는 테이블 삭제 요청 |
| 처리 | get_schema로 컬럼을 확인하고 DuckDB SQL을 생성한다. SQLGlot으로 한 문장과 허용 조회 및 INTO 부재를 검사하고 최대 50행을 반환한다. |
| 출력 | 집계 수치와 근거 SQL 또는 변경 요청 거부 |

## 자료의 예제와 학습 포인트

자료의 orders는 7개 가상 주문이다. 도시 합계의 기대값은 서울 2,090,000원, 제주 1,539,000원, 부산 124,000원이며 DROP 거부와 컬럼 오류 후 재확인이 과제다.

자료의 코드와 모델명은 당시 흐름을 이해하기 위한 예시다. 이 문서는 외부 API나 원문 코드를 실행한 결과가 아니다. 구현 전 사용 중인 SDK, 전송 방식과 패키지 버전을 현재 공식 문서와 대조한다.

## 적용할 조건과 피할 상황

자연어 질의와 스키마 주입을 배우기에 적합하다. 교육용 연결을 운영 DB의 읽기 전용 보장으로 간주하면 안 된다.

## 실패 조건과 해석 경계

예시 DB 연결은 seed를 위해 쓰기 가능하다. SELECT 최상위 허용만으로 외부 파일 접근과 부작용 함수 및 비싼 쿼리를 모두 제한하지 못한다.

## AI 설계 보완

아래는 원문의 수행 결과가 아닌 **AI 설계 제안과 원문 예시의 한계 분석**이다.

운영에서는 읽기 전용 계정, 테이블과 함수 허용 범위 및 쿼리 deadline을 둔다. 잘림 여부는 51번째 행 존재 등으로 명시하고 질문, SQL과 실행 계획을 검토한다.
