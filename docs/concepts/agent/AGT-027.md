## 정의와 필요한 이유

체크포인트는 실행 중 상태와 다음 위치를 저장해 대화와 중단 작업을 이어가는 장치다. 대화 식별자와 저장소 수명이 복구 범위를 정한다.

## 입력에서 출력까지

| 단계 | 구체적 내용 |
|---|---|
| 입력 | 대화 메시지와 thread_id |
| 처리 | 단계마다 상태를 저장한다. 같은 대화 ID로 상태를 조회하고 새 입력 또는 적절한 재개 명령으로 이어간다. |
| 출력 | 복구된 메시지, 다음 노드와 상태 이력 |

## 자료의 예제와 학습 포인트

자료는 메모리 저장은 프로세스 종료 시 사라지고 SQLite 및 PostgreSQL은 지속 저장에 쓴다고 설명한다. 같은 thread의 두 번째 연차 질문이 이전 대화를 이어받는 예가 있다.

자료의 코드와 모델명은 당시 흐름을 이해하기 위한 예시다. 이 문서는 외부 API나 원문 코드를 실행한 결과가 아니다. 구현 전 사용 중인 SDK, 전송 방식과 패키지 버전을 현재 공식 문서와 대조한다.

## 적용할 조건과 피할 상황

승인 대기, 대화 연속성과 장애 후 복구에 적합하다. 체크포인트를 대화 압축이나 사용자 인증과 같은 기능으로 보면 안 된다.

## 실패 조건과 해석 경계

thread_id를 아는 것만으로 접근을 허용하면 다른 사용자의 상태가 노출된다. 저장소가 있어도 외부 API 부작용과 상태 저장은 원자적이지 않을 수 있다.

## AI 설계 보완

아래는 원문의 수행 결과가 아닌 **AI 설계 제안과 원문 예시의 한계 분석**이다.

서버가 대화 소유자를 확인하고 저장소 생명주기를 유지한다. 재개 전 pending 상태를 확인하며 쓰기에는 멱등성과 결과 조정 절차를 둔다.

## AI 작성 복습 문답

**질문:** 체크포인터가 대화 길이도 자동으로 줄여 주는가?

**설명 답안:** 상태 저장과 컨텍스트 선별은 별개이므로 압축과 메시지 관리 정책을 따로 설계해야 한다.
