# AGT-021 캐싱으로 반복 비용을 줄인다

출처: **SRC-02**, 보조 HTML 구간 [#s-6e3ad387](https://tech-learning-hub.pages.dev/courses/ai-agent/complete-guide.html#s-6e3ad387). 사용자 제공 PDF와의 쪽별 대응 및 판독 상태는 [출처 대응표](../../../sources/SRC-02.md)에서 구분한다. 온라인 주소는 보관 HTML의 사이트 원문 링크이며 현재 온라인 내용과의 일치는 확인하지 않았다. 이 문서는 강의 자료를 바탕으로 AI가 재서술한 개념 설명이며 개인의 구현이나 운영 성과 기록이 아니다.

## 정의와 필요한 이유

캐싱은 고정 입력, 반복 조회와 동일 응답을 다른 계층에서 재사용해 비용을 줄인다. 데이터 신선도와 사용자 범위가 캐시 정확성을 결정한다.

## 입력에서 출력까지

| 단계 | 구체적 내용 |
|---|---|
| 입력 | 도구명, 정규화 인자, 사용자 범위와 조회 시각 |
| 처리 | 고정 정책과 도구 정의를 입력 앞에 둔다. 읽기 결과만 TTL과 키로 관리하고 개인 데이터는 사용자 및 권한 범위로 분리한다. |
| 출력 | 유효한 캐시 결과 또는 실제 조회 결과 |

## 자료의 예제와 학습 포인트

자료는 문서 3,600초, 날씨 600초, 주문 30초, 발송 0초라는 TTL 예시와 정렬 JSON 키를 보여 준다. 실패 결과와 쓰기 성공을 재사용하지 않도록 설명한다.

자료의 코드와 모델명은 당시 흐름을 이해하기 위한 예시다. 이 문서는 외부 API나 원문 코드를 실행한 결과가 아니다. 구현 전 사용 중인 SDK, 전송 방식과 패키지 버전을 현재 공식 문서와 대조한다.

## 적용할 조건과 피할 상황

반복되는 읽기와 안정적인 프롬프트 접두부에 적합하다. 쓰기를 실행하지 않고 보냈다고 응답하는 캐시는 부적합하다.

## 실패 조건과 해석 경계

공개 문서라도 권한에 따라 보이는 부분이 다르면 사용자 키를 무조건 생략할 수 없다. TTL 안에서도 중요한 상태가 바뀔 수 있다.

## AI 설계 보완

아래는 원문의 수행 결과가 아닌 **AI 설계 제안과 원문 예시의 한계 분석**이다.

캐시 키에 tenant, 권한 버전과 문서 버전을 포함하고 필요 시 무효화한다. 부작용 중복 방지는 캐시와 분리된 멱등성 계약으로 설계한다.

## AI 작성 복습 문답

**질문:** 도구 결과 캐시와 멱등키는 같은가?

**설명 답안:** 아니다. 캐시는 읽기 재사용이고 멱등키는 같은 쓰기 요청이 중복 수행되지 않도록 식별하는 계약이다.
