# AGT-024 왜 그래프로 만드나

출처: **SRC-02**, 보조 HTML 구간 [#s-fbc0dfea](https://tech-learning-hub.pages.dev/courses/ai-agent/complete-guide.html#s-fbc0dfea). 사용자 제공 PDF와의 쪽별 대응 및 판독 상태는 [출처 대응표](../../../sources/SRC-02.md)에서 구분한다. 온라인 주소는 보관 HTML의 사이트 원문 링크이며 현재 온라인 내용과의 일치는 확인하지 않았다. 이 문서는 강의 자료를 바탕으로 AI가 재서술한 개념 설명이며 개인의 구현이나 운영 성과 기록이 아니다.

## 정의와 필요한 이유

상태 그래프는 반복문 안의 판단과 도구 및 중단 분기를 노드와 엣지로 드러내는 표현이다. 흐름이 복잡할 때 상태 저장과 재개를 체계화한다.

## 입력에서 출력까지

| 단계 | 구체적 내용 |
|---|---|
| 입력 | 질문과 초기 상태 |
| 처리 | START에서 모델 노드로 가고 호출 필요 여부에 따라 tools 또는 END로 분기한다. 도구 뒤에는 관찰을 포함해 다시 모델로 돌아간다. |
| 출력 | 그래프 실행 상태와 최종 응답 |

## 자료의 예제와 학습 포인트

자료는 직접 루프, 미리 만든 ReAct와 직접 LangGraph를 비교한다. 승인 대기, 여러 회차의 대화, 복잡한 분기와 체크포인트가 도입 이유라고 설명한다.

## 적용할 조건과 피할 상황

중단 재개와 분기가 복잡한 작업에 적합하다. 단순한 두세 도구 루프는 직접 구현으로도 충분할 수 있다.

## 실패 조건과 해석 경계

그래프를 그렸다고 권한과 비용 및 오류 처리가 자동으로 해결되지는 않는다. LangGraph와 모델 호출 인터페이스의 책임도 구분한다.

## AI 설계 보완

아래는 원문의 수행 결과가 아닌 **AI 설계 제안과 원문 예시의 한계 분석**이다.

노드를 독립적으로 시험 가능한 입출력 변환으로 만들고 상태의 불변식과 종료 상태를 먼저 정의한다.
