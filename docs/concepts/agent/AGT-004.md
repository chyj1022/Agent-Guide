## 정의와 필요한 이유

도구, 스키마, 턴, 궤적, 메모리, HITL은 모델과 실행기의 책임을 나누기 위한 용어다. 같은 단어를 다른 의미로 쓰면 설계와 평가가 엇갈린다.

## 입력에서 출력까지

| 단계 | 구체적 내용 |
|---|---|
| 입력 | 자연어 목표와 도구 명세 |
| 처리 | 모델이 호출 요청을 만들고 실행기가 인자와 권한을 검사해 실행한다. 결과를 호출 ID에 연결해 다음 판단에 전달한다. |
| 출력 | 행동 기록과 최종 응답 또는 중단 상태 |

## 자료의 예제와 학습 포인트

자료는 함수 호출과 도구 호출을 유사한 개념으로 소개하고, ReAct를 판단과 행동 및 관찰의 반복으로 설명한다. 스크래치패드, 단기 및 장기 기억, 체크포인트와 인젝션을 함께 정의한다.

## 적용할 조건과 피할 상황

설계 문서, 팀 내 용어 합의, 로그 스키마 작성에 적합하다. 용어를 나열하는 것만으로 실행 계약을 대체하지 않는다.

## 실패 조건과 해석 경계

턴은 모델 호출 수, 도구 실행 수, 그래프 전이 수와 다를 수 있다. 추상적 설명에서 이를 한 숫자로 합치면 예산과 평가를 잘못 읽는다.

## AI 설계 보완

아래는 원문의 수행 결과가 아닌 **AI 설계 제안과 원문 예시의 한계 분석**이다.

step 정의와 집계 단위를 문서화한다. 기록은 공개 가능한 행동 요약과 도구 결과 중심으로 남기며 비공개 내부 추론의 노출을 요구하지 않는다.

## AI 작성 복습 문답

**질문:** tool calling을 받으면 함수는 이미 실행되었는가?

**설명 답안:** 아니다. 호출할 이름과 인자를 받은 단계이며 실제 실행은 호스트 코드가 담당한다.
