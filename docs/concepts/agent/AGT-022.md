출처: **SRC-02**, 보조 HTML 구간 [#s-28f6dda5](https://tech-learning-hub.pages.dev/courses/ai-agent/complete-guide.html#s-28f6dda5). 사용자 제공 PDF와의 쪽별 대응 및 판독 상태는 [출처 대응표](../../../sources/SRC-02.md)에서 구분한다. 온라인 주소는 보관 HTML의 사이트 원문 링크이며 현재 온라인 내용과의 일치는 확인하지 않았다. 이 문서는 강의 자료를 바탕으로 AI가 재서술한 개념 설명이며 개인의 구현이나 운영 성과 기록이 아니다.

## 정의와 필요한 이유

계획은 목표를 실행 가능한 단계와 의존성으로 나누고 반성은 결과의 누락과 오류를 점검한다. 검증 수단과 반복 상한이 있어야 추가 호출이 가치를 갖는다.

## 입력에서 출력까지

| 단계 | 구체적 내용 |
|---|---|
| 입력 | 복잡한 목표, 사용 도구와 현재 결과 |
| 처리 | 계획을 만들고 단계별 결과를 상태에 기록한다. 실패나 새 관찰로 계획을 조정하며 테스트 등 외부 기준으로 점검한다. |
| 출력 | 완료된 단계와 미완료 항목이 드러나는 결과 |

## 자료의 예제와 학습 포인트

자료는 5단계 이내 JSON 계획과 depends_on, 최대 2회 반성 예를 제시한다. 자기 검토가 맞는 답을 잘못 고칠 수 있고 모르는 사실은 도구로 확인해야 한다고 설명한다.

자료의 코드와 모델명은 당시 흐름을 이해하기 위한 예시다. 이 문서는 외부 API나 원문 코드를 실행한 결과가 아니다. 구현 전 사용 중인 SDK, 전송 방식과 패키지 버전을 현재 공식 문서와 대조한다.

## 적용할 조건과 피할 상황

코드 테스트와 계산 재검증처럼 확인 가능한 작업에 적합하다. 근거 없는 사실을 자기 비평만으로 확정하기에는 부적합하다.

## 실패 조건과 해석 경계

for문 안에서 plan 변수만 새 목록으로 바꾸면 이미 시작된 반복의 실행 계획이 갱신되지 않을 수 있다. 실행 결과를 무조건 done에 넣는 것도 잘못이다.

## AI 설계 보완

아래는 원문의 수행 결과가 아닌 **AI 설계 제안과 원문 예시의 한계 분석**이다.

계획 버전과 단계 상태를 명시하고 검증된 완료만 기록한다. 재계획 큐와 반성 예산을 실행기가 통제한다.

## AI 작성 복습 문답

**질문:** 반성을 추가하면 항상 품질이 오르는가?

**설명 답안:** 아니다. 외부 검증 기준이 없으면 같은 오류를 반복하거나 맞는 답을 바꿀 수 있다.
