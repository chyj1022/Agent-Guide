# AGT-016 무엇을 기억하고 무엇을 버릴 것인가

출처: **SRC-02**, 보조 HTML 구간 [#s-32f93b6a](https://tech-learning-hub.pages.dev/courses/ai-agent/complete-guide.html#s-32f93b6a). 사용자 제공 PDF와의 쪽별 대응 및 판독 상태는 [출처 대응표](../../../sources/SRC-02.md)에서 구분한다. 온라인 주소는 보관 HTML의 사이트 원문 링크이며 현재 온라인 내용과의 일치는 확인하지 않았다. 이 문서는 강의 자료를 바탕으로 AI가 재서술한 개념 설명이며 개인의 구현이나 운영 성과 기록이 아니다.

## 정의와 필요한 이유

기억은 최근 대화, 현재 작업 상태와 세션을 넘는 사실을 다른 수명으로 관리하는 설계다. 모두 대화 배열에 쌓으면 비용과 맥락 손실이 커진다.

## 입력에서 출력까지

| 단계 | 구체적 내용 |
|---|---|
| 입력 | 최근 메시지, 계획, 완료 단계와 사용자 선호 |
| 처리 | 작업 상태는 구조화 객체로 유지한다. 오래된 관찰은 실패 이유를 포함해 요약하고 장기 기억은 현재 질문과 관련된 것만 가져온다. |
| 출력 | 짧은 현황과 관련 사실이 포함된 다음 호출 입력 |

## 자료의 예제와 학습 포인트

자료는 TaskState의 goal, plan, done, findings, failed와 brief를 설명한다. 장기 기억에는 선호와 확정 결정을 남기고 일회성 질문과 추측을 제외하는 예를 제시한다.

자료의 코드와 모델명은 당시 흐름을 이해하기 위한 예시다. 이 문서는 외부 API나 원문 코드를 실행한 결과가 아니다. 구현 전 사용 중인 SDK, 전송 방식과 패키지 버전을 현재 공식 문서와 대조한다.

## 적용할 조건과 피할 상황

긴 작업과 세션을 넘는 개인화에 적합하다. 대화 전체를 영구 저장하는 것을 지능 향상과 동일시하지 않는다.

## 실패 조건과 해석 경계

유사도 0.9만으로 과거 기억을 덮어쓰면 서로 다른 사건이나 유효 시점의 사실을 잃는다. add reducer에 잘린 목록을 반환하면 실제 삭제 대신 추가될 수 있다.

## AI 설계 보완

아래는 원문의 수행 결과가 아닌 **AI 설계 제안과 원문 예시의 한계 분석**이다.

기억마다 출처, 확정 여부, 시각, 범위와 만료 정책을 둔다. 메시지 삭제는 사용 중 reducer의 삭제 의미에 맞춰 구현하고 재현 검사한다.

## AI 작성 복습 문답
