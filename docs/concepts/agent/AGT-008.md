# AGT-008 도구 설계는 description 이 절반이다

출처: **SRC-02**, 보조 HTML 구간 [#s-baa6057d](https://tech-learning-hub.pages.dev/courses/ai-agent/complete-guide.html#s-baa6057d). 사용자 제공 PDF와의 쪽별 대응 및 판독 상태는 [출처 대응표](../../../sources/SRC-02.md)에서 구분한다. 온라인 주소는 보관 HTML의 사이트 원문 링크이며 현재 온라인 내용과의 일치는 확인하지 않았다. 이 문서는 강의 자료를 바탕으로 AI가 재서술한 개념 설명이며 개인의 구현이나 운영 성과 기록이 아니다.

## 정의와 필요한 이유

도구 설명은 모델이 기능을 선택하는 인터페이스다. 대상, 사용 조건, 제외 조건과 반환 모양이 분명해야 잘못된 선택과 반복을 줄인다.

## 입력에서 출력까지

| 단계 | 구체적 내용 |
|---|---|
| 입력 | 주문 배송 상태나 교육과정 일정 질문 |
| 처리 | 이름과 description 및 인자 스키마를 보고 후보를 고른다. 서버는 고객 ID를 세션에서 주입하고 enum과 건수 범위를 검사한다. |
| 출력 | 권한 범위 안의 작은 조회 결과 또는 이유와 대안이 있는 오류 |

## 자료의 예제와 학습 포인트

자료는 search_orders의 상태 enum과 최대 20건 제한, 교육과정 카탈로그와 개인 신청 내역 및 문서 검색을 구별하는 설명을 보여 준다. 도구 선택만 시험하는 네 질문도 제시한다.

자료의 코드와 모델명은 당시 흐름을 이해하기 위한 예시다. 이 문서는 외부 API나 원문 코드를 실행한 결과가 아니다. 구현 전 사용 중인 SDK, 전송 방식과 패키지 버전을 현재 공식 문서와 대조한다.

## 적용할 조건과 피할 상황

서로 비슷한 기능을 가진 도구 세트에 적합하다. 구현을 모델이 알아서 추론할 것이라 가정하지 않는다.

## 실패 조건과 해석 경계

도구를 5~7개로 줄이라는 조언은 시작점이다. 적정 수는 선택 평가로 정한다. 출력 단순 문자열 절단은 JSON을 깨뜨릴 수 있다.

## AI 설계 보완

아래는 원문의 수행 결과가 아닌 **AI 설계 제안과 원문 예시의 한계 분석**이다.

도구 계약에 읽기 여부, 민감 인자의 서버 주입, 결과 페이지 커서, 오류 코드와 선택 반례를 추가한다.
