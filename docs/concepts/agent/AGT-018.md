# AGT-018 스트리밍으로 진행 상황을 보여 준다

출처: **SRC-02**, 보조 HTML 구간 [#s-c967a126](https://tech-learning-hub.pages.dev/courses/ai-agent/complete-guide.html#s-c967a126). 사용자 제공 PDF와의 쪽별 대응 및 판독 상태는 [출처 대응표](../../../sources/SRC-02.md)에서 구분한다. 온라인 주소는 보관 HTML의 사이트 원문 링크이며 현재 온라인 내용과의 일치는 확인하지 않았다. 이 문서는 강의 자료를 바탕으로 AI가 재서술한 개념 설명이며 개인의 구현이나 운영 성과 기록이 아니다.

## 정의와 필요한 이유

스트리밍은 긴 실행의 진행과 답변을 이벤트로 전달하는 사용자 인터페이스 계약이다. 실행 중 무엇을 하는지와 최종 종료를 구분해 알려야 한다.

## 입력에서 출력까지

| 단계 | 구체적 내용 |
|---|---|
| 입력 | 긴 질문과 모델의 응답 조각 및 도구 호출 조각 |
| 처리 | 호출 index별로 이름과 인자를 조립한다. 도구 실행 전후 진행 이벤트를 내보내고 최종 답이나 한도 도달을 명시한다. |
| 출력 | token, tool_start, tool_end, limit, final 같은 이벤트 흐름 |

## 자료의 예제와 학습 포인트

자료는 FastAPI StreamingResponse와 SSE의 data 줄 및 빈 줄 경계를 설명한다. tool_calls 조각을 index별로 합쳐야 서로 다른 인자가 섞이지 않는다고 강조한다.

자료의 코드와 모델명은 당시 흐름을 이해하기 위한 예시다. 이 문서는 외부 API나 원문 코드를 실행한 결과가 아니다. 구현 전 사용 중인 SDK, 전송 방식과 패키지 버전을 현재 공식 문서와 대조한다.

## 적용할 조건과 피할 상황

수십 초 이상 걸리는 작업과 중간 개입이 필요한 화면에 적합하다. 화면에 텍스트를 조금씩 보여 주는 것만으로 완료 보장을 대신하지 않는다.

## 실패 조건과 해석 경계

자료 코드의 tool_call_id 생략부는 그대로 실행 가능한 구현이 아니다. POST 스트림을 브라우저 기본 EventSource가 직접 보내지는 못하므로 클라이언트 방식을 맞춰야 한다.

## AI 설계 보완

아래는 원문의 수행 결과가 아닌 **AI 설계 제안과 원문 예시의 한계 분석**이다.

완성 전 인자 실행을 금지하고 명시적 상태와 이벤트 번호를 둔다. 사용자 화면에는 민감 인자와 내부 상태를 걸러서 보내고 연결 해제와 취소를 별도 처리한다.

## AI 작성 복습 문답

**질문:** 스트림 연결이 끊기면 성공인가?

**설명 답안:** 아니다. 완료 이벤트나 작업 상태 조회로 정상 완료와 네트워크 장애를 구분해야 한다.
