# AGT-009 구조화 출력으로 결과 모양을 고정한다

출처: **SRC-02**, 보조 HTML 구간 [#s-17a16470](https://tech-learning-hub.pages.dev/courses/ai-agent/complete-guide.html#s-17a16470). 사용자 제공 PDF와의 쪽별 대응 및 판독 상태는 [출처 대응표](../../../sources/SRC-02.md)에서 구분한다. 온라인 주소는 보관 HTML의 사이트 원문 링크이며 현재 온라인 내용과의 일치는 확인하지 않았다. 이 문서는 강의 자료를 바탕으로 AI가 재서술한 개념 설명이며 개인의 구현이나 운영 성과 기록이 아니다.

## 정의와 필요한 이유

구조화 출력은 프로그램이 사용할 결과의 키, 타입과 허용값을 제한하는 방법이다. 모양의 안정성과 내용의 정확성은 별개다.

## 입력에서 출력까지

| 단계 | 구체적 내용 |
|---|---|
| 입력 | 환불이나 배송 관련 문의 문장 |
| 처리 | category, urgency, reason, needs_human 같은 필드를 스키마로 요청하고 반환 상태와 검증 결과를 검사한다. |
| 출력 | 분류 계약에 맞는 객체 또는 거부와 불완전 응답 상태 |

## 자료의 예제와 학습 포인트

자료는 자연어로 JSON을 부탁하는 방법, 예시, JSON Schema와 특정 도구 강제를 비교한다. 분류 category는 환불, 배송, 결제오류, 상품문의, 기타로 제한한다.

자료의 코드와 모델명은 당시 흐름을 이해하기 위한 예시다. 이 문서는 외부 API나 원문 코드를 실행한 결과가 아니다. 구현 전 사용 중인 SDK, 전송 방식과 패키지 버전을 현재 공식 문서와 대조한다.

## 적용할 조건과 피할 상황

후속 분기, 집계, UI 렌더링과 리뷰 결과 교환에 적합하다. 사실 검증 자체를 대신하기에는 부적합하다.

## 실패 조건과 해석 경계

스키마는 근거 문장의 진실성을 보장하지 않는다. 원문의 source[start:end] in source 검사는 어떤 정상 슬라이스도 통과하므로 인용의 정당성을 검증하지 못한다.

## AI 설계 보완

아래는 원문의 수행 결과가 아닌 **AI 설계 제안과 원문 예시의 한계 분석**이다.

인덱스의 0<=start<end<=len(source)를 검사하고 주장에 연결된 인용 문자열과 정확히 대조한다. 거부, 출력 중단, 지원하지 않는 스키마도 별도 처리한다.

## AI 작성 복습 문답

**질문:** 스키마에 맞으면 답도 맞는가?

**설명 답안:** 아니다. 타입과 필드가 맞아도 분류나 근거 내용은 틀릴 수 있어 별도 검증이 필요하다.
