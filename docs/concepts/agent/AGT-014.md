# AGT-014 생각하고, 행동하고, 관찰한다

출처: **SRC-02**, 보조 HTML 구간 [#s-6ac9e9fb](https://tech-learning-hub.pages.dev/courses/ai-agent/complete-guide.html#s-6ac9e9fb). 사용자 제공 PDF와의 쪽별 대응 및 판독 상태는 [출처 대응표](../../../sources/SRC-02.md)에서 구분한다. 온라인 주소는 보관 HTML의 사이트 원문 링크이며 현재 온라인 내용과의 일치는 확인하지 않았다. 이 문서는 강의 자료를 바탕으로 AI가 재서술한 개념 설명이며 개인의 구현이나 운영 성과 기록이 아니다.

## 정의와 필요한 이유

ReAct는 다음 행동을 선택하고 실행한 결과를 관찰해 다시 판단하는 반복 구조다. 관찰이 다음 경로를 바꾼다는 점이 중요하다.

## 입력에서 출력까지

| 단계 | 구체적 내용 |
|---|---|
| 입력 | 지난주 매출 보고서를 작성하라는 목표 |
| 처리 | 판매를 조회하고 결과를 검토한 뒤 카테고리별 원인을 더 찾거나 보고서를 완성한다. 반복, 시간, 토큰과 동일 호출 한도를 매 단계 확인한다. |
| 출력 | 근거가 있는 보고서 또는 중단 사유와 부분 결과 |

## 자료의 예제와 학습 포인트

자료는 1,240건과 매출 8,300만원 및 전주 대비 12%라는 가상 관찰 뒤에 세부 원인을 조회하는 흐름을 보여 준다. 예시 한도는 15단계, 120초, 60,000토큰이다.

자료의 코드와 모델명은 당시 흐름을 이해하기 위한 예시다. 이 문서는 외부 API나 원문 코드를 실행한 결과가 아니다. 구현 전 사용 중인 SDK, 전송 방식과 패키지 버전을 현재 공식 문서와 대조한다.

## 적용할 조건과 피할 상황

관찰에 따라 탐색이 달라지는 분석에 적합하다. 고정 절차를 복잡한 자율 루프로 바꾸는 데 쓰지 않는다.

## 실패 조건과 해석 경계

동일 호출의 원시 JSON 문자열만 비교하면 키 순서가 바뀐 반복을 놓칠 수 있다. 루프 앞 시간 검사만으로 긴 단일 호출을 중단할 수도 없다.

## AI 설계 보완

아래는 원문의 수행 결과가 아닌 **AI 설계 제안과 원문 예시의 한계 분석**이다.

판단의 공개 설명보다 행동과 근거를 중심으로 기록한다. 인자를 정규화하고 각 도구 deadline과 전체 취소를 연결한다.

## AI 작성 복습 문답

**질문:** ReAct에서 관찰의 역할은 무엇인가?

**설명 답안:** 도구가 돌려준 사실이나 실패를 다음 행동 선택의 입력으로 제공한다.
