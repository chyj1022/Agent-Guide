# AGT-054 C-06, 코드 리뷰 에이전트

출처: **SRC-02**, 보조 HTML 구간 [#s-616ac0ed](https://tech-learning-hub.pages.dev/courses/ai-agent/complete-guide.html#s-616ac0ed). 사용자 제공 PDF와의 쪽별 대응 및 판독 상태는 [출처 대응표](../../../sources/SRC-02.md)에서 구분한다. 온라인 주소는 보관 HTML의 사이트 원문 링크이며 현재 온라인 내용과의 일치는 확인하지 않았다. 이 문서는 강의 자료를 바탕으로 AI가 재서술한 개념 설명이며 개인의 구현이나 운영 성과 기록이 아니다.

## 정의와 필요한 이유

C-06은 변경 목록과 diff 및 주변 코드를 읽고 리뷰 지적을 구조화해 전달하는 실습이다. 파일 위치와 위험 시나리오를 검증 가능하게 만드는 것이 목적이다.

## 입력에서 출력까지

| 단계 | 구체적 내용 |
|---|---|
| 입력 | 비교 기준 커밋과 저장소 변경 |
| 처리 | list_changed_files 뒤 파일별 get_diff를 보고 필요하면 read_context를 읽는다. 마지막에 Finding과 Review 스키마로 결과를 정리한다. |
| 출력 | summary, findings, approved와 파일 및 줄 위치 |

## 자료의 예제와 학습 포인트

자료 Finding은 file, line, severity, category, what, why, fix를 포함한다. diff는 12,000자에서 부분 검토임을 표시하며 승인 여부를 종료 코드에 연결하는 예를 든다.

자료의 코드와 모델명은 당시 흐름을 이해하기 위한 예시다. 이 문서는 외부 API나 원문 코드를 실행한 결과가 아니다. 구현 전 사용 중인 SDK, 전송 방식과 패키지 버전을 현재 공식 문서와 대조한다.

## 적용할 조건과 피할 상황

리뷰 보조와 프로그램이 읽을 지적 생성에 적합하다. 모델의 approved를 실제 병합 권한으로 곧바로 쓰면 안 된다.

## 실패 조건과 해석 경계

자료 read_context는 HEAD를 읽으므로 작업 트리 diff와 버전이 어긋날 수 있다. 조사 상한 이후 마지막 tool 요청에 대응 관찰이 없을 가능성도 처리해야 한다.

## AI 설계 보완

아래는 원문의 수행 결과가 아닌 **AI 설계 제안과 원문 예시의 한계 분석**이다.

검토 대상 base와 head를 고정하고 파일 및 줄이 실제 읽은 버전과 일치하는지 검사한다. 읽지 못한 범위를 남기고 고위험 지적은 재현 또는 정적 근거로 검증한다.
