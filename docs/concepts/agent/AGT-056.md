# AGT-056 C-08, MCP 서버를 만들고 붙인다

출처: **SRC-02**, 보조 HTML 구간 [#s-85ed8fd2](https://tech-learning-hub.pages.dev/courses/ai-agent/complete-guide.html#s-85ed8fd2). 사용자 제공 PDF와의 쪽별 대응 및 판독 상태는 [출처 대응표](../../../sources/SRC-02.md)에서 구분한다. 온라인 주소는 보관 HTML의 사이트 원문 링크이며 현재 온라인 내용과의 일치는 확인하지 않았다. 이 문서는 강의 자료를 바탕으로 AI가 재서술한 개념 설명이며 개인의 구현이나 운영 성과 기록이 아니다.

## 정의와 필요한 이유

C-08은 메모 기능을 MCP 서버 한 벌로 노출하고 여러 호스트에서 도구를 사용하는 실습이다. 표준 연결과 서버 자체의 경로 및 쓰기 책임을 배운다.

## 입력에서 출력까지

| 단계 | 구체적 내용 |
|---|---|
| 입력 | 메모 목록, 읽기, 쓰기 또는 키워드 검색 요청 |
| 처리 | FastMCP가 도구 목록과 호출 프로토콜을 제공한다. 서버는 notes 범위 안 경로를 검사하고 클라이언트가 도구들을 에이전트에 연결한다. |
| 출력 | 메모 내용, 검색된 줄 또는 생성 및 덮어쓰기 상태 |

## 자료의 예제와 학습 포인트

자료 도구는 list_notes, read_note, write_note, search_notes 네 개다. STDIO 서버와 어댑터 클라이언트, 코딩 호스트별 설정 예를 제시하며 UTF-8 입출력을 강조한다.

자료의 코드와 모델명은 당시 흐름을 이해하기 위한 예시다. 이 문서는 외부 API나 원문 코드를 실행한 결과가 아니다. 구현 전 사용 중인 SDK, 전송 방식과 패키지 버전을 현재 공식 문서와 대조한다.

## 적용할 조건과 피할 상황

한 기능을 여러 호스트에서 재사용하는 학습에 적합하다. 호스트의 승인과 샌드박스가 서버 내부에 자동으로 전파된다고 가정하면 안 된다.

## 실패 조건과 해석 경계

서버가 별도 프로세스라는 사실만으로 항상 샌드박스 밖이라는 뜻은 아니며 실행 환경마다 확인해야 한다. 기존 메모 덮어쓰기는 원문 코드에서 별도 승인이나 버전 보관이 없다.

## AI 설계 보완

아래는 원문의 수행 결과가 아닌 **AI 설계 제안과 원문 예시의 한계 분석**이다.

서버 실행 계정과 작업 디렉터리를 고정하고 읽기와 쓰기 권한을 나눈다. 덮어쓰기 전 버전 및 내용 해시를 확인하고 현재 호스트 설정과 전송 API를 공식 문서로 대조한다.

## AI 작성 복습 문답

**질문:** 도구를 네 호스트에 붙이면 코드도 네 벌 필요한가?

**설명 답안:** 서버 기능은 재사용할 수 있지만 각 호스트의 연결과 인증 및 권한 설정은 별도로 맞춰야 한다.
