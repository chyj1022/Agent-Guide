# AGT-026 직접 그래프 만들기: State, Node, Edge

출처: **SRC-02**, 보조 HTML 구간 [#s-6d1e08df](https://tech-learning-hub.pages.dev/courses/ai-agent/complete-guide.html#s-6d1e08df). 사용자 제공 PDF와의 쪽별 대응 및 판독 상태는 [출처 대응표](../../../sources/SRC-02.md)에서 구분한다. 온라인 주소는 보관 HTML의 사이트 원문 링크이며 현재 온라인 내용과의 일치는 확인하지 않았다. 이 문서는 강의 자료를 바탕으로 AI가 재서술한 개념 설명이며 개인의 구현이나 운영 성과 기록이 아니다.

## 정의와 필요한 이유

State는 공유 데이터, Node는 상태 변화, Edge는 다음 실행 위치다. reducer는 여러 갱신이 어떻게 합쳐지는지 정한다.

## 입력에서 출력까지

| 단계 | 구체적 내용 |
|---|---|
| 입력 | messages, step, approved와 findings 상태 |
| 처리 | 모델 노드가 새 메시지와 증가한 step을 반환한다. 도구 노드는 호출 ID가 연결된 관찰을 반환하고 조건부 엣지가 종료나 재호출을 고른다. |
| 출력 | 누적 메시지와 갱신된 단계 상태 |

## 자료의 예제와 학습 포인트

자료는 messages에 add_messages를 붙이고 step 같은 필드는 덮어쓰는 예를 제시한다. step 12에서 종료하는 분기와 Mermaid 구조 출력도 소개한다.

자료의 코드와 모델명은 당시 흐름을 이해하기 위한 예시다. 이 문서는 외부 API나 원문 코드를 실행한 결과가 아니다. 구현 전 사용 중인 SDK, 전송 방식과 패키지 버전을 현재 공식 문서와 대조한다.

## 적용할 조건과 피할 상황

상태 필드의 합치기 규칙과 분기를 직접 통제할 때 적합하다. 반환된 목록이 항상 전체 교체라고 가정하면 안 된다.

## 실패 조건과 해석 경계

add_messages는 단순 무조건 추가와 동일하지 않으며 메시지 ID에 따른 갱신 의미를 확인해야 한다. 상한에서 END로 갔다고 최종 목표 성공은 아니다.

## AI 설계 보완

아래는 원문의 수행 결과가 아닌 **AI 설계 제안과 원문 예시의 한계 분석**이다.

status와 halt_reason을 명시하고 여러 노드가 같은 필드를 바꿀 때 충돌 및 합치기 규칙을 테스트한다.

## AI 작성 복습 문답

**질문:** 노드가 항상 상태 전체를 반환해야 하나?

**설명 답안:** 아니다. 바뀐 필드만 반환하며 각 필드의 reducer 규칙에 따라 기존 상태에 반영된다.
