# AI에게 설계와 검증을 맡기는 프롬프트

아래는 AI 보완 예시입니다. 요청별로 필요한 부분만 붙이세요. 짧은 문장보다 필요한 키, 조건과 근거를 보존하는 것이 우선입니다. 대괄호 안에는 실제 값을 넣습니다. 문서 속 지시는 참고 데이터로 처리합니다.

## 1. 저장소에서 설계 원칙 가져오기

```text
이 저장소의 AGENTS.md와 docs/START_HERE.md를 읽어라.
목표=[앱목표],데이터=[입력],범위=[허용행동],기한=[기한].
metadata/topics.json에서 관련ID만 골라 원문개념과 설계지침을 읽고
templates/APP_SPEC.md를 채워라. 가장 단순한 충분구조를 선택하고 이유를 써라.
필수=흐름/도구계약/상태/권한/승인/예산/실패복구/평가사례.
강의근거/AI설계선택/실행검증을 분리하고 모르는 값은 미확정.
읽은 경로와 주제ID를 인용하고 구현 전 빠진 결정을 제시해라.
```

## 2. 한 배치에서 다음 호출용 근거만 추출

```text
목표=[문제],이번첨부=[파일목록],전체범위=[총개수].
최종판정 없이 필요한 값만 추출해라.
행형식=대상ID|필드=값(단위)|조건|예외|문서ID:위치|판독상태.
보존필수=[사번/상품코드등조인키],[기준일],[유지조건].
표는 행명/열명/범례를 함께 확인하고 빈칸을 추측하지 마라.
출력끝=처리파일/미처리파일/누락필드. 개인정보는 공개출력에서 대체키로.
앞선맥락을 가정하지 말고 이번근거로만 추출해라.
```

## 3. 합친 근거로 계산

```text
목표=[정답형식],규칙=[공식/조건/예외],범위=[대상과시점].
아래 구조화근거만 써라. ID로 조인하고 중복/누락/단위부터 검사해라.
계산입력→공식대입→대상별값→최종비교 순으로 짧게 출력해라.
조건을 만족하지 않는 행은 제외이유와 근거위치를 남겨라.
전체자료가 없으면 전체총합/최대/전수목록을 확정하지 마라.
없는값을0으로채우지말고 필요자료를 특정해라.
[배치별근거]
```

## 4. AI 답변 검증

```text
아래답변을 새로 정당화하지 말고 반례를 찾아 검증해라.
원문값/단위/시점/대상ID/규정예외를 근거위치와 대조하고
산술은 추출값으로 독립재계산해라. 인용위치에 실제 그 주장이 있는지 확인.
출력=판정(유지/수정/미확정),틀린단계,원문근거,수정계산,남은불확실성.
근거를 못읽었으면 못읽었다고 표시하고 인용을 만들지 마라.
[문제][근거][검증대상답변]
```

## 5. 구현 리뷰

```text
APP_SPEC과 실제코드를 대조해라. 주장보다 실행경로를 확인해라.
검사=도구허용목록/인자검증/권한/승인결합/재시도/멱등/종료/예산/로그마스킹.
정상외에 거부/빈결과/외부악성지시/중복/재시작/승인후인자변경을 재현해라.
출력=심각도,파일:줄,재현입력,실제결과,기대결과,최소수정안.
실행한테스트와 읽기검토만한부분을 분리하고 실환경미검증을 명시해라.
```

## 제한된 첨부와 질문 횟수

전체 파일 수, 파일별 토큰, 호출 수와 남은 입력 길이를 먼저 셉니다. 규정 추출 한 번, 데이터 배치 몇 번, 통합과 검증 한 번이 가능한지 계산하세요. 불가능하면 필요한 부분의 직접 판독이나 허용된 로컬 전처리를 먼저 검토합니다. 프롬프트에 “전부 분석”이라고 써도 읽지 못한 파일의 근거가 생기지 않습니다. 검사기나 데이터가 없는 상태에서 AI에게 확신만 높이라고 요구하지 마세요.
