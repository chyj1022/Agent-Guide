# 적용 예시, GPU 가격 비교 앱

이 문서는 AI가 작성한 가상 설계입니다. 실제 사용자의 데이터나 운영 성과를 공개하지 않습니다. 앱을 설계할 때 개념을 어떻게 연결하는지 보여 주며, 실행된 가격 비교 서비스가 아닙니다.

## 목표와 데이터 계약

사용자는 GPU 모델과 사용 조건을 넣고 비교 가능한 상품 목록과 근거를 받습니다. 구매나 예약은 제외합니다. 입력 가격의 통화, 시간/월 청구 단위, GPU 수, 지역, 수집 시각이 확인되지 않으면 숫자가 작다는 이유만으로 가장 싸다고 판단하지 않습니다. 모델 이름이 같아도 메모리 용량이나 인스턴스 구성이 다르면 다른 비교 대상일 수 있습니다.

가상 원천 스키마는 `offer_id/provider_id/model_id/memory_gb/gpu_count/region/currency/billing_unit/price/observed_at/source_ref`입니다. 필드가 원본에 없으면 `unknown` 상태를 남기고 필요에 따라 비교에서 제외합니다. 상품 키와 모델 키의 관계를 확인하지 않고 이름으로 조인하면 행이 늘어날 수 있으므로 조인 전후 행 수와 키의 유일성을 검사합니다.

## 가장 작은 구조

```text
UI 조건 입력
→ API: 사용자와 입력 크기 확인
→ 질문 파서: 모델/지역/예산을 구조화
→ 코드: 인자와 허용 필터 검증
→ catalog 도구: 조건에 맞는 원천 데이터 조회
→ 코드: 단위 정규화, 비교 가능 여부, 순위 계산
→ 설명 생성: 근거가 있는 결과만 서술
→ 출력 검증: 순위, 수치, 출처와 누락 범위 대조
→ UI: 결과와 수집 시각, 비교 제외 이유 표시
```

순위 계산과 누락 판정은 결정적 코드가 맡습니다. 모델은 애매한 질문을 해석하고 결과를 설명합니다. 관찰을 보고 다음 조사 도구를 고를 필요가 생길 때만 제한된 에이전트 루프를 추가합니다. 정적인 CSV 조회라면 MCP 서버도 필수는 아닙니다. 여러 앱이 같은 카탈로그 기능을 공통으로 쓸 때 MCP 어댑터의 이득을 검토합니다.

## 하네스와 도구

도구는 `search_catalog(filters)`와 `get_offer(offer_id)` 두 읽기 기능으로 시작합니다. 결과는 상태, 자료, 원천 버전과 시점을 반환합니다. 0건은 `empty`, 권한이 없으면 `denied`, 네트워크 일시 장애는 `transient_error`로 구분합니다. 처음 버전에는 임의 SQL, 셸 명령, 결제 도구를 노출하지 않습니다.

각 실행에 허용 필터, 단계/도구/비용 한도와 기한을 둡니다. 모델이 같은 조건으로 빈 검색을 반복하면 추가 호출 대신 조건을 넓힐지 사용자에게 확인하거나 누락 상태로 종료합니다. 결과에 근거 없는 할인율이나 가격을 생성하면 완료하지 않고 한정된 재작성 또는 실패로 처리합니다.

## 평가 사례

- 같은 모델의 가격 두 개: 코드가 비교한 값과 출력 순위가 일치해야 합니다.
- 시간당 가격과 월 가격: 가정한 월 사용 시간과 환산 과정을 보여 주거나 비교하지 않아야 합니다.
- 통화가 없는 가격: 자동으로 USD라고 가정하지 않아야 합니다.
- 오래된 수집 시점: 최신 결과라는 표현을 하지 않아야 합니다.
- 중복 모델 키: 조인 후 행 증가가 의도된 변형인지 검토해야 합니다.
- 자료 일부 미첨부: 전체 시장 최저가라고 답하지 않아야 합니다.
- 상품 설명에 악성 지시 포함: 외부 전송이나 파일 접근이 일어나지 않아야 합니다.

이 설계는 AGT-001~006의 워크플로 선택, AGT-007~012의 도구 계약, AGT-041의 검색, AGT-044~047의 평가와 연결됩니다. 위 사례를 실제 fixture와 코드로 검사하기 전에는 성능이나 정확도를 수치로 주장하지 않습니다.
