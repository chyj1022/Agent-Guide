# 결과를 검증하고 회귀를 잡는 방법

AI 보완 설계 지침입니다. AGT-034~035, AGT-044~047, AGT-058, AGC-019, AGC-029, AGC-034와 연결됩니다. “답이 자연스럽다”는 것은 계산, 권한과 출처가 맞다는 검증이 아닙니다.

## 검증을 세 단계로 나누기

첫째, 도구 자체를 결정적인 입력으로 검사합니다. 스키마 오류, 단위 변환, 빈 결과, 타임아웃과 권한 거부를 모델 없이 재현해야 합니다. 둘째, 워크플로의 궤적을 봅니다. 정해진 도구를 몇 번 사용했는지, 승인 전에 쓰기가 없었는지, 실패 후 올바르게 중단했는지 검사합니다. 셋째, 사용자 관점의 결과가 정확하고 근거가 있는지 평가합니다.

모델이 “검증 완료”라고 답한 문장을 증거로 삼지 마세요. 인용한 문서의 행/열/페이지와 실제 값을 대조하고, 공식의 입력값을 독립적인 계산으로 확인합니다. 같은 모델에게 같은 문맥에서 다시 질문하면 같은 오류를 반복할 수 있습니다. 비교에 사용한 값과 계산기를 분리하면 오류 위치를 좁힐 수 있습니다.

## 평가 사례 만들기

아래 사례는 가상 앱에 맞춰 수정할 출발점입니다.

| 사례 | 기대 결과 | 검증할 기록 |
| --- | --- | --- |
| 정상적인 읽기 후 설명 | 근거 있는 답과 완료 상태 | 출처 ID와 도구 결과 |
| 일부 문서 미첨부 | 부분 범위 표시, 전체 확정 안 함 | 처리 목록과 누락 목록 |
| 표 범례와 빈칸 | 미제공과 미확인 구별 | 행명, 열명, 범례 |
| 단위/시점이 다른 가격 | 정규화 또는 비교 불가 | 통화, 단위, 기준시각 |
| 도구 인자가 잘못됨 | 실행 전 거부 | validation 오류 |
| 외부 문서의 악성 지시 | 권한/정책 유지 | 실행 안 된 위험 도구 |
| 승인 후 대상 변경 | 재승인 또는 거부 | 인자 해시와 상태 버전 |
| 응답 유실 후 중복 요청 | 중복 효과 억제 또는 상태 대사 | 멱등 키와 외부 작업 ID |
| 예산 소진 | 추가 호출 없이 중단 | 실제 호출 수와 비용 |
| 사용자 취소/서버 재시작 | 명시적인 상태와 안전한 복구 | 상태 전이와 남은 작업 |

## 지표와 임계값

결과 정확도, 출처 유효율, 도구 선택, 승인 위반, 누락 인식, 반복 호출, 지연과 비용을 따로 봅니다. 치명적인 권한 위반을 평균 정확도에 섞어 감추지 않습니다. 임계값은 사업 위험과 검증 사례를 근거로 정하며 이 저장소의 임의 숫자를 조직 기준으로 쓰지 않습니다.

사전/사후 성과 보고서는 모집단, 학과별 인원, 가중 평균, 기준일, 설문 응답 편향을 확인합니다. 상관관계만으로 취업이나 성적의 개선 원인을 확정할 수 없습니다. 인터뷰와 설문, 운영 제약이 충돌하면 관측 사실, 해석, 가설과 추가 검증 계획을 나눠 씁니다. 낮은 점수 학과만 나열하는 보고서 대신 커리큘럼의 요구 역량 불일치와 실행 제약을 근거로 연결하세요.

## 변경 후 다시 확인할 범위

프롬프트, 모델, 도구 설명, 스키마, 검색기, 문서 버전 중 하나가 바뀌어도 고정 평가셋을 재실행합니다. 모든 호출 순서를 하나로 강제하기보다 금지 행동, 필수 증거, 예산과 종료 같은 불변 조건을 검사합니다. 실제 모델을 쓰는 테스트와 오프라인 모의 테스트의 결과는 별도 보고합니다.
