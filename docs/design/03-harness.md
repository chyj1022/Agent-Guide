# 하네스, 실행을 계속할지 결정하는 코드

AI 보완 설계 지침입니다. AGT-007~022, AGT-024~030, AGC-010~015와 연결됩니다. 하네스는 모델을 호출하는 바깥 코드와 실행 규칙입니다. 모델의 다음 행동 제안을 실제 실행으로 옮길지 판단하고, 상태와 실패를 기록합니다.

## 실행 루프

`입력 검증 → 상태 읽기 → 한도 확인 → 모델 호출 → 제안 검증 → 승인 확인 → 도구 실행 → 결과 기록 → 완료 검사`를 기본 루프로 둡니다. 모델이 답을 내놨다는 사실만으로 완료 처리하지 않습니다. 필요한 근거가 있고 출력 계약을 만족했는지 검사합니다. 반대로 실패나 거부를 관찰했는데 같은 호출을 무제한 반복해서도 안 됩니다.

상태 예시는 `pending/running/waiting_approval/completed/failed/cancelled/budget_exceeded`입니다. 각 전이에 허용 조건을 정합니다. 승인 대기는 실패가 아니고, 결과가 없는 검색과 네트워크 장애도 다릅니다. 상태를 문자열 하나로만 두지 말고 원인 코드와 재개 가능 여부를 함께 저장하세요.

## 실행 한도는 중첩해서 적용

| 한도 | 세는 위치 | 초과했을 때 |
| --- | --- | --- |
| 모델 단계 수 | 각 모델 호출 전 | 새 호출을 중단하고 부분 결과 반환 |
| 도구 호출 수 | 재시도를 포함한 실제 실행 전 | 더 실행하지 않고 원인 기록 |
| 금액/토큰 | 호출 전 예상량 예약, 호출 후 실제량 정산 | 남은 예산 내에 안전한 호출만 허용 |
| 전체 시간 | 모든 단계의 공통 기한 | 대기/재시도도 남은 시간으로 제한 |
| 단일 도구 시간 | 도구 실행 경계 | 취소 요청 후 실제 취소 여부 확인 |

SDK의 timeout은 외부 작업이 취소됐다는 보장이 아닐 수 있습니다. 결제 요청 후 응답이 끊겼다면 “실패”라고 즉시 다시 결제하지 말고 외부 작업 ID로 상태를 조회합니다. 가격 단가가 없는 토큰 수만으로 비용을 확정하지 않습니다.

## 재시도와 재개를 구분

읽기 작업의 일시적 오류는 제한 횟수, 지수 백오프와 지터를 적용할 수 있습니다. 인증 실패, 잘못된 인자, 영구적인 거부에는 같은 인자로 반복하지 않습니다. 외부 쓰기는 멱등 키와 제공자의 중복 처리 보장이 있는지 먼저 확인합니다. 같은 키에 다른 인자가 들어오면 기존 결과를 재사용하지 말고 충돌로 거부합니다.

체크포인트는 “우리 코드가 어디까지 갔는지”를 보존합니다. 이미 외부로 보낸 이메일을 되돌리지 않습니다. 외부 호출 직후 저장 전에 프로세스가 죽는 간격을 고려해 intent/outbox, 외부 작업 ID, 대사 작업 또는 보상 절차를 설계합니다. 메모리 딕셔너리에 결과를 넣는 교육용 예제로 분산 환경의 exactly-once를 주장할 수 없습니다.

## 승인 결합

승인에는 사용자, 실행, 도구 이름, 정규화된 인자의 해시, 상태 버전, 만료 시각을 묶습니다. 승인 후 대상과 금액이 바뀌면 승인을 다시 판정합니다. 화면의 “승인” 문자열이나 모델의 “사용자가 동의했다”는 주장만으로 실행하지 않습니다. 승인 토큰의 저장과 검증은 서버 책임입니다.

## 프레임워크로 옮길 때

노드는 한 가지 책임을 가지며 입력과 상태 변경을 명시합니다. 라우팅은 반환값을 enum으로 제한하고, 도구 노드 앞에 정책 검사를 둡니다. 체크포인터는 스레드 상태, 별도 store는 실행을 넘는 기억에 해당합니다. 이 구별은 [LangGraph 공식 persistence 문서](https://docs.langchain.com/oss/python/langgraph/persistence)를 2026-10-31에 확인한 보완입니다. 실제 DB, SDK 버전, 동시성 및 승인 재개 동작은 해당 환경에서 검증해야 합니다.

교육용 제어 예제는 [examples/harness](../../examples/harness/README.md)에 있습니다. 이 코드는 실제 모델, MCP 서버, 장기 실행 인프라를 연결하지 않습니다.
