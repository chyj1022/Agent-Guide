# 데이터와 컨텍스트를 잃지 않게 하기

AI 보완 설계 지침입니다. AGT-016~017, AGT-041, AGC-012, AGC-021~022와 연결됩니다. 컨텍스트는 모델이 이번 호출에서 참고할 수 있는 입력입니다. 데이터베이스에 저장됐다는 이유만으로 현재 호출이 그 내용을 알고 있는 것은 아닙니다.

## 원본을 읽기 전에 출력부터 정하기

문서를 모두 요약하라고 시키면 결론에 필요한 식별자나 예외 조건이 빠질 수 있습니다. 먼저 문제에서 필요한 판단을 식으로 바꿉니다. “A2 사용 팀 중 초과 과금 최대”라면 `대상=플랜A2`, `초과량=max(0,사용량-계약수×인당제공량)`, `추가요금=초과량×단가`, `비교키=팀ID`가 필요합니다. 단가와 수치의 단위 및 적용 시점도 보존해야 합니다. 계산 공식은 실제 첨부 규정과 대조해야 하며 이 문서의 예시는 가상입니다.

그다음 필요한 파일을 고릅니다. 정책은 공식과 예외를 주고, 팀 보고서는 계약과 사용량을 줍니다. 임직원 명부는 사람 단위의 유지 조건이나 사번 조인이 필요한 문제에서만 추가합니다. 기능 미지원 문제에 초과요금 전체 표나 명부를 무조건 넣을 이유는 없습니다.

## 배치 추출 계약

자료가 많으면 파일마다 같은 구조로 추출합니다. `문서ID/버전/대상ID/필드/값/단위/조건/예외/페이지/판독상태`가 기본입니다. 사람이 나중에 맞춰야 할 사번과 상품 코드를 요약에서 버리지 않습니다. 표의 빈칸은 “미제공”인지 “미확인”인지 범례로 확인하고 구별합니다.

```text
문제 목적에 필요한 값만 추출. 계산/최종판정은 하지 마라.
출력=대상ID|필드=값(단위)|조건|예외|문서ID:p쪽|상태
상태=확인/미기재/판독불가/미첨부. 원문 표현과 추론을 분리.
식별자, 기준일, 규정 예외는 생략 금지. 표는 행명과 열명을 함께 확인.
처리한 파일명과 미처리 목록을 끝에 적어라. 없는 값은 추측하지 마라.
```

첨부 제한은 프롬프트를 잘 쓰는 것만으로 사라지지 않습니다. 45개 상품 중 9개만 읽었다면 전체 위반 상품을 확정할 수 없습니다. 로컬 전처리가 허용되면 먼저 필요한 열만 기계적으로 추출해 통합합니다. 허용되지 않으면 배치별 근거를 보존하고 답변 범위와 미처리 수를 분명히 합니다. 정해진 질문 횟수 안에 전수 처리가 불가능하면, 가능한 범위의 결과와 한계를 구분해야 합니다.

## RAG도 증거의 완전성을 보장하지 않음

검색은 관련 후보를 찾습니다. 검색 결과가 없다는 사실은 원문에 없다는 증명이 아닙니다. 문서 ID, 버전, 날짜, 청크 위치, 접근 범위를 붙여 반환합니다. 최신 운영 정책과 과거 문서가 섞이면 날짜만이 아니라 적용 대상과 효력 조건으로 재정렬합니다. 최신 문서가 모든 역사적 질문의 정답은 아닙니다.

답변에는 사실과 출처 위치를 묶습니다. 인용한 페이지에 실제 그 값이 있는지, 여러 단위나 시점을 섞지 않았는지 확인합니다. 모델의 자연어 설명을 다시 읽히는 것만으로 계산 검증을 대신하지 말고 추출값과 공식을 코드로 검사하세요.

## 압축할 때 보존할 것

목표, 현재 결정, 아직 모르는 것, 근거 ID, 권한, 예산과 다음 작업을 보존합니다. 대화 요약은 원문 명령의 권위를 늘리지 않습니다. 외부 문서에 든 악성 지시가 요약에 들어가도 데이터의 출처를 유지해야 합니다. 민감한 식별자는 공개 답변에서는 가리되, 내부 조인에는 접근 통제된 대체 키로 정확성을 유지합니다.
