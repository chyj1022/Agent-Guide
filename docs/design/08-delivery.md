# 배포와 해커톤에서 끝까지 완성하기

AI 보완 설계 지침입니다. AGT-036~039, AGT-048~059, AGC-032~037과 연결됩니다. 작은 정상 흐름 하나를 끝까지 연결하고, 가장 중요한 실패 경로를 보여 주는 것이 구성 요소만 많은 데모보다 검토하기 쉽습니다.

## 구현 순서

1. 입력 한 개와 예상 결과 한 개를 고정합니다. 실제 데이터 사용 권한과 공개 범위를 확인합니다.
2. 모델 없이 데이터 도구와 계산을 검사합니다. 단위, 대상 키와 누락을 먼저 잡습니다.
3. 모델 어댑터를 넣고 구조화된 조건을 받습니다. 모델 이름과 SDK 버전은 실제 환경에서 선택하고 잠급니다.
4. 하네스에 허용 도구, 종료 조건, 예산과 오류 상태를 둡니다.
5. 화면에 결과, 근거, 진행 상태와 재시도 가능한 오류를 표시합니다.
6. 필요한 경우에만 승인 UI, MCP 서버와 장기 상태 저장을 추가합니다.
7. 정상, 누락, 거부, 예산 소진의 고정 사례를 다시 실행하고 데모 스크립트를 만듭니다.

## 데모가 끊겨도 설명 가능한 상태

검색 API가 멈추면 캐시나 가상 데이터를 사용할 수 있지만 사용자에게 시점과 대체 상태를 알려야 합니다. 가상 데이터를 실시간 결과라고 제시하지 않습니다. 실패했다고 사라지는 스피너 대신 실패 코드, 완료된 범위와 다음 행동을 표시합니다. 스트리밍의 “작업 중” 이벤트도 성공 결과와 구분합니다.

## 배포 체크

환경 변수 예시는 이름만 넣고 비밀값을 저장소에 넣지 않습니다. 인증, 사용자별 실행 격리, 요청 크기와 속도 제한, 로그 보존, 상태 DB와 외부 작업 대사를 확인합니다. 로컬 메모리 저장과 디버그 서버는 운영 배포의 내구성을 보장하지 않습니다. 실행 중지가 외부 작업 취소까지 보장하는지도 구분합니다.

해커톤 시간표는 팀 상황에 맞게 정합니다. 요구사항, 도구 계약, 정상 흐름, 실패 검증, 화면 연결, 리허설마다 완료 조건을 둡니다. 마지막까지 기능을 추가하기보다 검증되지 않은 연결을 줄이고 작동 범위와 미완료 사항을 설명할 수 있게 합니다.
