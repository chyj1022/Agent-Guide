# 먼저 무엇을 읽을까

에이전트를 잘 만드는 일은 모델을 여러 개 붙이는 일과 같지 않습니다. 사용자가 원하는 결과를 정하고, 모델이 선택할 부분과 프로그램이 보장할 부분을 나누는 일부터 시작합니다. 이 가이드에서는 강의 개념을 읽는 경로와 앱을 실제로 설계하는 경로를 연결합니다.

## 초보자 경로

“가격이 가장 싼 GPU를 찾아 줘”라는 요청을 예로 들어 봅시다. 가격 파일을 읽고 단위를 맞춰 최솟값을 계산하는 과정은 정해진 코드로 처리할 수 있습니다. 모델은 질문의 조건을 해석하고 결과를 설명할 수 있습니다. 여기서 자동 구매까지 맡기면 결제 권한, 승인, 실패 후 중복 주문 문제가 추가됩니다. 같은 화면에서도 필요한 자율성은 달라집니다. 이 장면은 AI가 만든 가상 적용 예시입니다.

먼저 AGT-001~006의 에이전트와 워크플로 구별을 읽고, AGC-001~009의 위임과 통제를 읽으세요. 그다음 [요구사항 가이드](design/01-requirements.md)를 따라 결과와 금지 행동을 적습니다. 관련 ID의 실제 경로는 [개념 색인](CONCEPTS.md)에 있습니다.

## 설계하는 AI의 경로

1. 사용자의 목표, 입력 데이터, 성공 조건, 기한, 허용 행동을 추출한다.
2. [작업별 경로](ROUTES.md)로 필요한 주제만 고른다. 원문 전체를 무작정 컨텍스트에 넣지 않는다.
3. 선택 이유와 주제 ID를 함께 기록한다. “강의에 있으므로 쓴다”는 도입 근거가 아니다.
4. [APP_SPEC](../templates/APP_SPEC.md)의 미확정 항목을 명시하고 최소 앱 구조를 설계한다.
5. 도구 입력과 결과, 상태, 예산, 승인 및 실패 경로를 정의한다.
6. 외부 의존성 버전을 고정하고, 실제 도구 환경의 계약 테스트를 통과시킨 뒤 구현 범위를 넓힌다.

## 근거를 읽는 법

`SRC-01`과 `SRC-02`는 사용자 제공 PDF입니다. 개념 문서는 보관 HTML 본문을 판독 보조로 이용한 재서술입니다. 쪽별 대응표의 자동 후보는 OCR 텍스트의 유사도 결과이며 각 문장이나 그림을 정확히 확인했다는 뜻이 아닙니다. 표의 정렬, 코드의 실행 여부, 최신 제품 동작을 추정으로 메우지 마세요.

설계 지침의 예시와 수치는 별도 표시가 없으면 AI 작성 가상 예시입니다. 학습 자료 보유, 설계 문서 작성, 오프라인 테스트, 실서비스 검증은 서로 다른 상태입니다.
